# 琴伴 · 钢琴练习室

本机运行的钢琴练习 App：输入原曲歌名，联网查找乐谱，选择版本导入后按自己的速度练习。

## 启动

macOS 双击 **启动琴伴.command**，构建并打开 `http://127.0.0.1:8792`。需要 Node.js >=22.19，启动器会自动查找本机的新版本 Node。

更新源码后，如果旧服务仍在运行，请在旧启动终端按 Control+C，再双击启动器；只刷新网页不会更新 Node 服务内存中的找谱逻辑。关闭启动终端或按 Control+C 可停止本机服务。

```sh
npm install
npm run build
npm start
```

`npm run dev` 在同一个本机 8792 服务中监听前端构建更新，修改后刷新网页。

## 页面与练习

- 顶部：练习室、我的曲库、AI 找谱、音频转谱；右上角识谱任务、导入乐谱与 AI 设置。
- 练习侧栏：速度、左右手开关、节拍器、小节循环、音量、五线谱/简谱/钢琴卷帘切换、跟随、移调、编辑与导出。底部播放栏保留播放/暂停、进度、速度与常用快捷开关。
- 布局栏：顶栏、侧栏和钢琴键盘均可独立收起；「专注」只保留乐谱、播放按钮和右上角退出入口。iPad 竖屏默认专注，iPhone 横屏也默认专注；横竖屏分别记住布局选择，收起面板、旋转屏幕不重置播放进度。
- iPhone 使用底部导航、列表曲库与「继续练习」入口；练习设置以抽屉展开，键盘按需显示并可横向滑动。页面支持屏幕安全区域，浏览器刷新后保留布局偏好。
- 中央：乐谱占满剩余空间，按连续系统分行。一行内多个小节的五线首尾相接，每行起点才出现谱号、调号，不再按小节分成卡片。
- 简谱同样连续分行，每行共用右手/左手标签，以小节线分隔。播放位置、高亮与点击定位共用原音符时间线。

支持20–300 BPM变速：可以拖动速度条，也可以直接输入整数，按回车或离开输入框生效；播放中改速保留当前拍位。无效输入会恢复原值，“原速”恢复曲谱速度。练习变速不改写曲谱原速。另有左右手分开播放、节拍器、按小节循环、半音移调、空格播放/暂停。MusicXML/XML、压缩MXL、MIDI、琴伴JSON可直接导入；导出MusicXML、双轨MIDI、JSON，或打印为PDF。

## 数字乐谱与改编

所有导入结果默认使用数字音符重新排版，五线谱、双手简谱与钢琴卷帘共享音高、时间轴、左右手和混合拍号数据。原始图片仅在「原图参考」中对照，不会在原图加载后自动替换数字谱面。钢琴卷帘按实际音高和精确起止显示，复杂时值不能可靠排版时可用它查看全部音符。

「编辑与改编」可修改单音音高、时值、落点和演奏手，也能替换所选音符同一时刻、同一只手的和弦。支持大三、小三、属七、大七、小七、减三和挂四；另一只手及其他时刻的音符保留。新增和弦音沿用所选音符时值，已有位置按低到高保留时值。

选中音符后，「演奏效果」提供 pp–ff 力度、0–100% 自定义力度、重音／强重音、断奏／保持音、颤音、上下波音和上下行琶音。力度与重音改变实际发声力度；断奏保留书写时值、缩短发声至45%；保持音保留完整时值。颤音按约每拍8个交替音展开，波音先主音、辅助音、再回主音；辅助音按书写字母及调号确定，也能指定半音或全音，所需升降记号会标在装饰音上。琶音作用于同一时刻同一只手的整个和弦，按方向错开起奏，各音保留原结束时刻。预览最多8拍，关闭编辑器会停止预览。

「连接下一同音」为相接的同手、同声部同音添加延音线：数字谱保留两个可编辑音头，播放合并为一次起音，后续音沿用首音力度。修改音高、时值或加入冲突效果会解除无效连接。整曲播放、练习循环和MIDI共用同一发声展开逻辑；五线谱、简谱显示标记，钢琴卷帘展示实际发声音高与起止。JSON保留全部设置；MusicXML使用标准记号并附带可选演奏元数据，以便重新导入琴伴时保留逐音设置。这些效果支持撤销、重做和另存修改版，不额外调用识谱模型。

整首调式转换采用同主音大调／自然小调规则，实际转换音阶内的音高与调号，不生成新的音乐；调外音保留原音高并显示数量，需试听判断改编效果。未标注调式的导入谱必须先指定原调式。小调简谱使用以6为主音的记法。所有改动支持撤销、重做，首次保存另存修改版；未校对草稿的标记继续保留。MusicXML与JSON保留调式和小节时间轴，MIDI保留实际音高及已指定的大小调。视图转换和规则改编均不调用AI，不改变识谱模型或思考强度。

## 打印乐谱与 PDF

练习室谱面右上方点击 **打印乐谱**（或从导出菜单进入），选择五线谱、简谱或已有的原图参考，然后点击 **下载 PDF** 或 **打印乐谱**。PDF 在浏览器本地生成，不依赖服务器，网页版同样可用。整首谱按 A4 纵向分页，保持每行完整，并附曲名、作者、乐谱原速与页码；导出使用当前移调与编配，不包含播放高亮或控制按钮。钢琴卷帘模式进入时默认导出五线谱；修改后不再匹配的原谱不会作为打印选项。数字谱存在暂不支持的节奏时会提示错误，不会跳过该行生成残缺 PDF。

## 网页版（GitHub Pages）

在线打开：https://dns0129.github.io/Open_Piano_Player/

`npm run build:pages` 生成纯静态网页到 `dist-pages/`（默认部署在 `/Open_Piano_Player/` 子路径，可用 `PAGES_BASE=/其他路径/` 覆盖）。网页版包含全部曲库、五线谱/简谱、钢琴播放、变速、分手、循环、移调、导出，以及本地 MusicXML/MXL/MIDI/JSON 导入和浏览器内音频转谱；联网找谱、图片/PDF 识谱、网易云导入和本机共享曲库需要 Node 服务，网页版会给出说明而不会发起这些请求。

## 云端曲库仓库（score-repo/）

`score-repo/` 是随 Git 同步的曲库：GitHub `main` 分支即云端副本，其他电脑 `git pull` 后重新构建即可得到同一份曲目。每首曲目一个规范化 JSON（`scores/<id>.json`），`index.json` 记录标题、拍号、小节数、音符数、来源类型、入库时间和文件 SHA-256；`index.mjs` 由工具生成并静态导入全部曲目，App 启动时自动并入「我的曲库」。

```sh
npm run scores:add -- 导出的乐谱.json --description "一句说明"   # 新增或按 ID 更新（保留首次入库时间）
npm run scores:verify                                             # 校验清单、文件、SHA-256、乐谱结构和 index.mjs
npm run scores:list
```

App 导出的琴伴 JSON（`{ "score": {...} }`）可直接加入。曲目 ID 只能用小写字母、数字和连字符。新增曲目通过 Pull Request 合并到 `main`，`.github/workflows/score-repo.yml` 会对改动执行同样的校验；手工改动曲目文件而不更新清单会因 SHA-256 不一致而失败。仓库为私有时，曲目只对有权限的账号可见。

## 通用多页钢琴谱 PDF

2026-10-18 升降记号策略 `accidentals-v2-20261018`：单图、谱行识别和独立复读共用专项提示词，检查密集和弦中的记号归属、调号与逐小节临时升降状态、还原号、八度和跨小节延音。请求仍固定 `gpt-6.1-sol` / `high`；结果与用量记录保存提示词版本，旧提示词的缓存、检查点和相同 PDF 自动复用不代替新识别。历史任务和人工校对不会被删除。

昨晚五首的本机重识别入口：

```sh
npm run scores:reread-five
npm run scores:reread-five -- --run --import --publish
```

第一条只检查本机 `.local/batch-five-20261018/private-jobs.json` 和 `.local/full-score-jobs/` 内五份原始 PDF、30页对应的全部谱行图片，模型调用为0。范围为《Merry Christmas Mr. Lawrence》6页、《Eutopia》五线谱4页、《天龙八部之宿敌》5页、《IF YOU》6页和《golden hour》9页；另检查《宿敌》p3-s3及《IF YOU》p1-s5的原图，缺图时整批不启动。源目录可用 `--source` / `--jobs` 指定。

第二条用当前新版代码新建5个任务（不加载旧 runtime，不发送旧音符答案），每行识读和独立复读均核对实际模型、high档位与提示词版本；最多并发4次请求，不自动重试失败的计费调用。结果、原始回答、图片哈希、用量和续跑凭据保存在私有目录 `.local/batch-five-high-accidentals-v2/`。再次执行会继续本批未完成部分；已返回但复读或结构失败的行需在任务中重试或校对，不自动覆盖。不同原谱或新的一轮实验应通过 `--out` 使用独立目录。限流、缺行、结构失败或复读失败会保留任务并停止整批入库。

只有五首全部完整返回、结构与复读检查通过时，`--import` 才把新版本写入 `score-repo/` 并更新本机生产构建，保留旧版并标注“AI草稿待校对”；独立复读存在音符分歧也会记录，不冒充人工确认。`--publish` 提交这5个曲目和生成的索引并正常推送 `main`，不强制推送；GitHub Pages 工作流随后构建云端曲库。未传这两个参数不会写曲库或推送。仓库曲库在本机和 Pages 使用同一份乐谱 JSON；本机新任务的原图仍在私有任务目录，只有逐行人工确认后才进入已校对任务曲库。静态 Pages 本身不执行模型调用。已运行的本机 Node 服务需重启才能加载新版提示词；此入口使用新的 Node 进程，不依赖旧服务的内存配置。

上传其他钢琴双手谱 PDF（最大50 MB、200页），会逐页检测谱行并显示全部页面缩略图。用户可检查范围、补框漏检的行、调整裁切，并明确排除封面或空白页。跳过含音乐的页面只能作为片段，不能标成完整全谱。

整谱逐行识别并做第二次独立核对，默认全局最多并发4行、每个新谱行仍完整识别并独立复读（最多2次模型调用），每次最长10分钟。开始前只做本机 PDF 渲染和谱行范围检查，不调用模型；可以停止、刷新后从顶部「识谱任务」继续。任务、原PDF及裁图保存在本机 `.local/full-score-jobs/`，任务不保存AI密钥；恢复会核对原PDF的SHA256。旧任务已完成的转写与人工校对保留，未完成行及重试改走 GPT；首次继续旧任务前保留私有状态备份。

已校对曲库以本机磁盘任务为准：全部谱行人工确认、来源范围确认及结构检查通过后，自动加入「我的曲库」，无需再点击导入。打开 App、进入曲库或切回窗口时会重新读取；同一台电脑的不同浏览器共享这些已完成乐谱及原谱图片，不依赖测试浏览器的 localStorage/IndexedDB。已有合格任务自动补入，重启服务后仍可读取。请备份整个 `.local/full-score-jobs/`（含每份任务的 `job.json`、原PDF及 `.image` 图片），仅备份浏览器数据不足以保留共享曲库。

## 乐器音色

练习设置栏的 **音色** 新增 **醇厚三角钢琴**、**温暖小提琴** 和 **柔和弦乐合奏**，并保留标准、柔和、明亮钢琴和轻量合成。点击旁边的 **试听**，用同一小段原创旋律比较音色。选择成功后保存在当前浏览器，下次打开继续使用；未保存过选择时默认醇厚三角钢琴。

钢琴使用 [Salamander Grand Piano](https://github.com/Tonejs/audio/tree/869b6f8d9cddb47d966238c012041480b1ce517a/salamander) 的30个真实MP3录音采样（Alexander Holm，[CC BY 3.0](https://creativecommons.org/licenses/by/3.0/)），约2.01MB，从A0到C8按小三度采样，以最近根音移调覆盖88键。醇厚三角钢琴参考 Steinway 的温暖听感，基于 Salamander Yamaha C5 录音加入低中频共鸣、随力度变化的高频、圆润起音、延长释音与短立体声空间混响。柔和与明亮是同一采样库的EQ/包络预设；当前为单层采样，通过增益与滤波处理力度。

小提琴使用14个独奏录音，弦乐合奏使用20个分音区录音（低音提琴、大提琴组、中提琴组、小提琴组），合计约2.93MB，来源为 [VSCO 2 Community Edition](https://github.com/sgossner/VSCO-2-CE/tree/440300901dfe9275fd84e0b7763af1f8443ae62e)（Sam Gossner、Simon Dalzell；剪辑 Elan Hickler / Soundemote，[CC0](https://creativecommons.org/publicdomain/zero/1.0/)）。保留真实弓弦和揉弦，经过起音修整、音量匹配和180ms交叉淡化循环，支持持续长音；乐器自然音域之外以最近根音移调延伸。独奏小提琴沿用标准科学音高，其他源文件的八度命名已按 C3=中央C 转换。

全部MP3和作者/许可说明均随源码放在 `public/audio/piano/`、`public/audio/violin/` 和 `public/audio/strings/`，构建前校验SHA256，运行时只从应用自身资源读取，也支持 GitHub Pages 子路径。首次播放或试听时按需准备所选音源，显示加载进度；钢琴预设共用一套缓存，小提琴与合奏各自缓存。文件缺失或损坏会明确报错，可重试或手动选择轻量合成。音色切换继续使用同一播放时钟，保留当前播放位置、左右手和循环设置；跳转进弦乐长音时从循环内继续。自然播完保留释音与空间尾音，手动暂停和停止同时淡出混响。

`python3 scripts/prepare-string-assets.py` 可重新制作弦乐素材（需要 numpy、scipy、ffmpeg 和网络）；普通安装、构建和播放使用已经打包的文件，无需重新下载。素材清单记录固定源版本、原始路径与处理前后SHA256。

`output/timbres/` 中保留三段约21秒的MP3试听。开发时可用 `node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 5173` 启动源码服务，再运行 `node scripts/render-instrument-demos.mjs` 重新导出；此可选工具需要额外提供 Playwright、Chromium 和 ffmpeg。也可用 `QINBAN_PLAYWRIGHT_MODULE` 指定 Playwright 模块路径、`QINBAN_CHROMIUM` 指定浏览器路径。

## 按歌名联网找谱

1. 在 **AI 找谱** 输入任意歌名，可补充歌手避免重名。
2. 服务默认并行查询 **IMSLP 国外钢琴谱、Mutopia 钢琴目录、GitHub 公开 MIDI 目录、DuckDuckGo（HTML/Lite为同一渠道）、搜狗、Internet Archive乐谱档案、Bing HTML**。这些是7个独立远程渠道；专业谱库与档案渠道各自查询其公开馆藏，不冒称全网。查询不限制在内置目录。
3. 「可直接导入的乐谱」排在前面；已解析验证的 MIDI 显示音符数、钢琴／合奏标记。点击「直接导入练习」即可打开五线谱、简谱并播放。结果标题或「打开并筛选」进入App内版本浏览器，支持按格式、来源渠道及已验证钢琴来源筛选。
4. 版本浏览器能继续进入公开的版本页，发现嵌入PDF和原图；文件与网页分别展示，保留原站链接。MusicXML/MXL/MIDI直接导入，PDF进入全页预览与完整识谱，图片进入选区识别。来源要求验证码、登录或付费时显示原因，仍可在浏览器查看原站。
5. 返回结果按歌名、歌手和乐谱关键词筛选、排序，并按真实地址去重；同一结果保留命中的多个渠道。来源链接随谱保存到本机曲库。

国外钢琴谱：支持常见古典作品的中外文曲名对照。输入 **野蜂飞舞** 会同时检索原名和 **Flight of the Bumblebee / Rimsky-Korsakov**，结果页显示外文曲名，并提供外文搜索及 IMSLP 入口。还收录 Hummelflug、Le vol du bourdon、Полёт шмеля 等本曲名称；别名只用于查真实谱源，不生成音乐，也不推断未注明的作者。未知曲名保留原文正常联网查询，不伪造翻译。

IMSLP 按真实版本标题 “For Piano” 提取公开钢琴独奏预览，排除其他乐器、双钢琴及低清缩略图；Mutopia 读取目录实际乐器字段，限定独奏钢琴。谱源标记只证明来源的乐器描述，导入后还需检查实际图片。野蜂飞舞已有经过核实的 Kevin W. K. Yeung 钢琴独奏版（7页PDF），仅处理该公开文件地址，保留 CC BY-SA 3.0 / Non-PD US 原始标注；公开预览页始终标为预览，不拼造缺页，不处理受限下载。

实测路径：搜索 **青花瓷** → 「可直接导入的乐谱」中已验证的钢琴 MIDI → 「直接导入练习」。公开文件来自 [callmeyyzx/midi](https://github.com/callmeyyzx/midi)，实测解析出1,355个音符、双钢琴声部，不是出版社原版五线谱；未找到明确许可时按源站标注显示，不虚构授权。目录及已解析候选缓存30分钟；目录、验证文件与最终下载固定到同一 GitHub 提交，避免更新后版本错位。匹配需源文件名或元数据支持曲名和附加限定词；文件缺少歌手信息时，加歌手可能不返回该 MIDI，可只用曲名查询并核对版本。

各渠道分别显示有结果、受限、无匹配或连接错误；某个渠道失败不会阻断其他渠道的结果。查询并行上限3，每渠道最多7秒、总计最多20秒。实际有效结果缓存2分钟并标注缓存，以减少重复查询；验证码、空结果或无关网页不会缓存成成功。

免费公开搜索可能临时要求验证或限流；Bing返回的相机、歌词、MV等无关结果会被过滤，HTTP 200也不等于找到了谱。完全没有有效结果时明确显示失败并提供外部搜索入口，不绕过验证码、登录或付费限制。已实测搜狗可返回现代歌曲谱源、Internet Archive可返回古典乐谱；这不保证任一免费渠道持续可用。

后台另有Brave Search API、Tavily、Serper官方适配。仅在服务器向`scoreSearch.search()`显式传入`searchConfig`中的`braveApiKey`、`tavilyApiKey`或`serperApiKey`时调用；没有配置就不调用、不计成功。当前没有这些Key的设置界面，也没有用真实Key验证，不能把协议适配当作已验证的稳定服务。

App不会作曲、凭记忆编写原曲、自动填补缺失页。`compose`及无谱面按标题编曲都在服务端禁用。内置的4首简易练习编配仅作为随时可用的示例曲目；搜索同时可匹配精选的公开MusicXML版本。

「支持任意歌名查询」不保证每首歌都有免费、完整、可自动导入的谱面。部分原站需要登录、购买或只提供预览；App仅处理公开可获取文件。预览页会标明，不冒充整曲。

## 音频转谱

在 **音频转谱** 上传 WAV、MP3、M4A、OGG、FLAC 等浏览器可解码的音频（最大50 MB）。页面显示原音频试听、实际振幅波形和时长；选择0.25–120秒片段后，可自动估计或手动指定20–240 BPM，按八分/十六分音符网格转写。识别灵敏度可选标准、保留弱音或减少杂音；减少杂音也可能遗漏弱音。

识别使用 [Spotify Basic Pitch 1.0.1](https://github.com/spotify/basic-pitch-ts) 官方多音模型，模型和权重随本机App构建，校验固定SHA256。优先使用WASM加速；不兼容时自动回退本机CPU。音频只在浏览器内解码，通过后台Worker本机识别，不上传给Pi、DeepSeek或搜索服务，也不消耗聊天额度。取消操作会终止本次Worker。浏览器能否解码某格式取决于设备；解码失败可先转换为WAV或MP3。

结果可预览五线谱/简谱、导出MIDI、保存到我的曲库并导入练习室；导入后也可导出MusicXML/JSON或打印。原始音频只保留在当前页面内存，刷新后需重新选择；转写谱保存至浏览器曲库。

优先使用钢琴或单一乐器音源。多乐器混音、人声、混响、踏板及噪声可能产生漏音或多余音符，结果明确作为待校对草稿。拍号暂设4/4，调号按音高分布估计，左右手以中央C音区划分，速度估计可能有半/倍速歧义；主旋律模式取每次起音的最高识别音，不创作伴奏。当前没有逐音符编辑器，可重新设置BPM与网格转写，或导出MIDI到制谱软件精修。

## 网易云分享链接导入

点顶部「导入乐谱」→「粘贴网易云分享链接」。可粘贴整段分享文字，也可使用歌曲/乐谱完整链接。歌曲链接会先列出乐谱版本；选择后展示全部返回页的缩略图、总页数和完整性状态。

接入第三方开源 [NeteaseCloudMusicApiEnhanced](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced) 4.41.1 的 `sheet_list`、`sheet_preview` 与扫码登录模块，不是网易官方开放 API。需要登录时点击「扫码登录」，由用户使用手机网易云 App 扫码并确认。登录仅保存在 `.local/netease-session.json`（目录 700、文件 600），不返回 Cookie 给浏览器，不写入浏览器存储或日志；「退出登录」删除本机会话。第三方模块在隔离子进程调用，原始日志不输出；仅开放这几个固定操作，不启动其独立 API 服务或音乐解锁功能。

只有当前账号可以访问的原图才能导入。接口总页数与页清单不一致、明确标记为预览/权限受限、页码缺失、重复地址或重复图片时，阻止全谱导入。接口不提供总页数时，必须对照原站输入正确页数并核验钢琴双手五线谱。只接受指定网易云图片来源的 PNG/JPEG；不猜图片地址，不把封面当作谱页，也不续写缺页。第三方未公布完整响应结构，未支持的结构会显示错误，不将空结果伪装成成功。

确认后，服务端按页序保留原始图片合并成多页 PDF，进入现有「全页检查 → 全谱识别 → 逐行校对 → 导入曲库 → 钢琴播放/跟谱」流程，最多 200 页、50 MB。获取图片与音符识别准确性分别检查，校对仍不可省略。关闭导入窗口会停止浏览器侧请求和二维码轮询；登录有效期、资源权限与第三方接口可用性以网易实际返回为准。

自动化测试使用明确标记的本地替身数据，不代表实际网易云资源已获取。已按用户实际操作产生的脱敏返回结构适配 `data: [{sheetId,url,pageNumber,...}]` 页表；该次实际返回 6 条页记录，但没有提供可信的总页数，因此仍须核对原站总页数。分享文字中的《曲名》会保留为导入名称；来自其他乐谱 ID 的混入页会被拒绝。当前工具对网易云页面的访问被拦截，实际谱页下载、完整性与识谱结果仍以用户操作后的逐页检查为准；代码接入不等于该曲已下载或识别成功。

## 当前准确性边界

- 图片素材先排除网页中明确的照片、封面、头像及其他乐器分谱。解码后检查实际五线、双谱表及音乐墨迹；钢琴实物照片、无谱封面、空白五线纸、六线 TAB 和缺少双手谱表的素材不能发给钢琴识谱。几何只能证明谱面结构，来源没有明确钢琴独奏标注时，须在预览中核对并勾选确认钢琴双手谱；确认不能绕过实际图片检查。
- PDF统一逐页检查范围、识别全部谱行，再逐行校对；不会默认只识别首行。图片选区仍支持连续谱行、原图拖框及当前整页。提交Pi的裁块保留原始像素，每块最多4MB，超限需缩小范围，不静默压缩细线。
- AI识谱仍需对照原谱与试听校对；禁止只返回部分谱段却当作完整结果。标题与来源保留实际范围，不允许续写补曲。实测《晴天》清晰首小节9音与独立手读音高、起点、时值一致；整页识别仍有错音，不能以返回JSON作为准确性证明。
- MIDI播放保留原始时值。重排五线谱/简谱支持本曲3:2三连音；其余普通节奏沿用十六分网格，独立复声部合并为和弦及延音线，原谱视图保留原始声部书写。中途速度/拍号/调号变化、弱起按固定拍号重排、反复不展开等情况会在导入提示中说明。
- 默认使用真实钢琴采样，也可切换轻量合成钢琴；尚未接入麦克风评弹或MIDI键盘自动评分。

### 识别完成后修改音符

在练习室右上点击“修改音符”，选择小节，再点击谱面或音符按钮。可以调整半音、八度、常用时值与附点，试听单音，补音、补和弦音、删音并撤销/重做。需要移动落点或填写三连音等特殊时值时，展开“调整落点与特殊时值”；拍数统一按四分音符计算，其他音符不会自动后移。

首次点击“保存为修改版”会在本机曲库新增一份修改版，原乐谱与原始 PDF/图片保留。重新打开修改版可继续编辑、保存和导出，五线谱、简谱和播放共同使用修改后的音符。修改版重新排版，不改写原始图片；关闭编辑窗口会放弃本次未保存的修改。

### DeepSeek 与 Pi 共用识谱流程

完整 PDF 导入完成逐页扫描后，在“识谱服务商”选择 Pi Agent / ChatGPT 或 DeepSeek。DeepSeek 使用本机保存的 API Key，固定 `deepseek-flash`、high 思考强度，按 DeepSeek API 用量计费。图片以原始清晰度发送到所选服务商，密钥只由本机服务端读取。

两个服务商共用同一套完整性要求：全页范围检查 → 每行双手谱识别 → 不提供首轮答案的独立复读 → 音高、拍位、时值、调拍号、休止与延音差异比较 → 原图逐音人工校对 → 全部谱行审核与跨行接续检查 → 导入现有曲库、播放和原谱跟随。不能凭曲名补写、用部分结果冒充全谱或自动确认人工审核。

任务创建后固定服务商；切换服务商需重新选择范围并建立新任务。相同 PDF、人工校对行缓存和识别检查点按模型隔离，DeepSeek 不使用 GPT 的识别结果。每行首轮结果立即保存，核对失败可只补核对；最多 4 个模型请求并发。限流、余额不足与认证失效停止继续派发，不自动重试付费调用。任务状态、调用数、模型、耗时和官方返回的 tokens 分别记录在本机；缺失用量不当作零。

DeepSeek 返回值仍经过相同本地音符及结构校验；支持图片与独立复读不代表任意曲谱达到零错误。真实验收记录位于 `evidence/deepseek-recognition/`，其中单行测试不能代替六页整曲准确率和完整自然播放验证。
