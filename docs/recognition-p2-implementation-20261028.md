## 2. 发布门禁和固定口径

`recognition:versions` 检查当前声明，`recognition:release` 检查实际识别实现、模型输入文本/图像预处理指纹，以及已通过的固定回归证据；两者均纳入 `npm run check`。提示词文本改变或图像预处理改变时，旧响应的离线回放不能提供新视觉质量证明。改变来源、参考内容、事件单位、对齐方式或评分范围，也不能继续沿用同一回归集版本。

默认策略为：同范围、同参考比较，不允许严格匹配下降、新增未匹配预测、失败/部分输出/拒识增加、错误完成增加或已具备的书写证据退化。没有独立参考的字段保留未知，不将零分母写成 100%。这些规则检查当前已登记范围，不代表对任意未来作品的质量保证。

统一评分使用四分音符拍，容差 1e-4，以手别、MIDI、起拍和时值进行一对一最大匹配；重复音、和弦音和额外事件不去重。谱行使用冻结的行内时间，整首前奏曲使用文档时间；照片子集使用事先声明的小节编号和小节内拍位，不事后移动拍位补分。普通书写音头和延音合并后的播放事件分别计数。

JS 评分结果另外由不导入 App 解码器的 Python 程序核验。它复算严格匹配、音高/手别和具备参考的书写字段；本轮 42 个可评分的“区域—条件”组合一致。未标注照片仅统计状态，不产生逐音准确率。

公开的 [版本清单](recognition-versions.json)、[语料登记](recognition-regression-corpus.json)及[发布证据](recognition-release-evidence.json)只含版本、指纹、范围与汇总。原谱、参考音符、原始回答、用量原日志和模型凭据不进入 Git。CI 核验公开证据与当前代码是否绑定；没有私有语料的 CI 不会假装重新完成了真实识谱。

## 3. 实际离线回归

| 同一批 P0 离线恢复 | 1292 | 935 | 933 | 只恢复既有响应，不是新模型识读 |

| 前奏曲旧 high 条件 | 604 | 605 | 594 | 与播放事件口径分开 |
| 前奏曲旧 max 条件 | 604 | 604 | 600 | 历史档位实验，本轮未切换模型档位 |
| 手机整照的已标注子集 | 36 | 16 | 16 | 24 张中仅 2 张、3 小节有视觉参考；参考未经人工确认 |

上述条件在本次解码器重构前后均无退化，独立复算一致。不能把各行分母相加后报告一个总准确率：同一作品/区域在不同条件重复出现，照片参考等级也不同。

前奏曲历史“602 音”是延音合并后的播放事件；本次保留书写音头，普通事件为 604，另有倚音单独处理。因此不回写旧报告。low 条件的全局书写拍位匹配，也不等同于其旧小节对齐指标。

P1 两行的纸面字母、八度和有效升降值，本次可与同版独立 MusicXML 比较，142/142 一致；这是已存在响应的新增字段评分，不是新增模型调用。图上是否显式印了某个升降符号、休止、版式和全部演奏记号尚无完整独立参考，仍为未知。

《幻听》的 1068 音先前参考属于已对原谱审核的转录，不能直接晋升为独立金标准。BWV846 的 549 个播放事件和 617 个书写音头，也没有在本轮建立独立的冻结页行适配。二者记录在候选登记中，没有用既有校对稿或模型一致率补齐真值。

本轮 `providerCalls=0`。这说明工程重构未改变当前已测结果，不支持“模型看图能力提高了某个百分点”的结论；固定数据都是开发集，尚无作品保留集保证。

## 4. 显式真实读取入口

prepare/evaluate 默认离线。只有选择 `live` 并提供足够预算，才动态加载模型读取入口。固定 PDF 核心范围为 16 行，每行一次、无自动补救或独立复读；预算不足会在请求前拒绝。请求只含白名单中的原图、几何与必要源谱上下文，不传参考音符或旧答案。

真实读取保存请求前 pending、逐行响应与协议指纹；遇未完成提供方请求、限流或认证问题停止后续派发，未返回范围仍留在分母。缺失请求数/用量保留未知，本地图像准备失败则明确为零提供方请求。已有运行目录拒绝覆盖；该入口不自动续发状态不明的付费请求。

```sh
# 准备私有固定清单：所有输出位置必须为新位置
node scripts/with-node.mjs recognition:regression prepare \
  --dense DENSE_ROOT --prelude PRELUDE_ROOT --phone PHOTO_ROOT \
  --p1 P1_CONTEXT_ROOT --p1-first P1_INITIAL_ROOT --out NEW_CORPUS_DIR

# 以旧源码快照为解码基线，离线比较并登记证据
node scripts/with-node.mjs recognition:regression evaluate \
  --suite CORPUS_DIR/suite.json --baseline-code VERIFIED_PREVIOUS_SOURCE \
  --out NEW_EVALUATION.json --attest

# 只有明确进行新的付费识读时才执行；本轮没有执行
node scripts/with-node.mjs recognition:regression live \
  --suite CORPUS_DIR/suite.json --out NEW_LIVE_DIR --budget 16

# 新读取之后，加入原始 live-result 再评分和独立核验
node scripts/with-node.mjs recognition:regression evaluate \
  --suite CORPUS_DIR/suite.json --baseline-code VERIFIED_PREVIOUS_SOURCE \
  --live-result NEW_LIVE_DIR/live-result.json --out NEW_LIVE_EVALUATION.json --attest
```

## 5. DeepSeek、计量与任务恢复

DeepSeek 的产品选项和策略都标为实验/第二意见，保留显式选择及历史任务，默认仍是 GPT。官方 Chat Completions 文档说明思考模式不支持 `required` 或指定工具名；本轮保留 high/auto，不通过关闭思考来强制提交。[官方说明](https://api-docs.deepseek.com/api/create-chat-completion/)

没有工具调用但同次响应包含单个完整 JSON 时，经同一紧凑协议和结构校验接收，额外请求为零。普通说明、缺字段、截断、多个工具调用和无法完整识读仍然保留疑点或拒收。没有进行新的 DeepSeek 准确度实验，不能把减少漏提交等同于看图更准确。

识别计划汇总首读、失败恢复、分段和复读的实际用量，按审计 ID 去重，恢复检查点不会重复累计。某次只有 output 时保留 output，不能补 input/total 为 0，也不能把部分已知总和当作完整费用。

托管端仍要求有效的 input/output 才能正常结算；total、缓存和思考字段只在提供方实际报告时保存，不再用相加或补零代替。计价、预留、积分、退款、未知请求的人工核账和订阅逻辑保持原规则。旧运行的迟到检查点回调核对 runVersion，不能覆盖新运行状态。

## 6. Skill 1.3.0 的交付事务

原谱校验、XML/MIDI 生成、JSON、可选 SVG 和报告先写入输出旁的暂存目录，每个完成文件记录哈希与大小；完整验证后再发布正式目录，并附 `artifact-manifest.json`。artifactSetComplete 表示文件集齐全，转录是否已复核仍由 checked/draft、blockers 和原图复核证据决定。

输入、页图清单、工具实现与构建选项绑定指纹。显式 `--resume` 会验证已完成文件并复用；改过的输入、用户修改文件、未知产物或正在运行的构建不能被覆盖。旧正式输出默认保留；完整输出只有验证清单和全部文件一致时才能按 resume 读回。

实际测试终止了正在构建的子进程，确认正式目录未出现半成品；恢复后复用了已校验的 XML，并完成完整交付。另测文件篡改、输入/选项变化、同输出并发竞争及原生 Verovio 重绘。页图准备与实际看图能力不是这个产物事务的证明范围。
