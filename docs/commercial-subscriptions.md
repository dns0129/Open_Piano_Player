# 商业版订阅、积分与扫码支付

实现版本：`2026-10-28-v1`。仅商业账号运行时启用，不改变本地开发版识谱、模型设置与原曲库。

## 套餐与计费

| 产品 ID | 套餐 | 人民币价格 | 积分 | 有效期 |
| --- | --- | --- | --- | --- |
| `light` | 轻享版 | ¥29 | 300 | 一个订阅月 |
| `standard` | 标准版 | ¥59 | 800 | 一个订阅月 |
| `professional` | 专业版 | ¥129 | 2,000 | 一个订阅月 |
| `topup` | 补充积分包 | ¥19 | 150 | 180 天 |

首次建立积分账户赠送 30 积分，长期有效。各档识别质量相同，每条完整左右手谱行 5 积分；这是一个选区的价格，用户应按实际谱行框选。保存原谱、数字谱导入、编辑、播放和练习不扣识谱积分。

价格、积分和账单版本由服务端目录决定并快照进订单，客户端金额、积分、所属用户一律不作为入账依据。调整目录后须更新版本，原订单按其快照兑现；真实成本尚需商户和模型付费环境验证，本轮未产生真实扣款或模型消费。

## 月周期与续订

本版采用微信 Native／支付宝当面付扫码购买，**没有签约代扣，不自动扣款**。用户主动购买一个月，提前续订排在已购周期之后；改选其他套餐也从下一个未购买周期生效。未来周期的积分已登记但不可提前消费。页面展示当前套餐和各批次生效、到期时间。

以香港时间的原始账单日计算月周年，短月取该月最后一日，再回到原始账单日。例如 1 月 31 日 → 2 月 28 日 → 3 月 31 日。月积分当期有效不累计，补充积分支付后立即生效，优先使用最早到期批次。没有自动续费开关，用户到期不再购买即可停止。

## 冻结、结算与补偿

- 服务端核对用户确认的规则版本和总积分；新任务只冻结需要新识别的谱行。余额不足不入队。
- 冻结、任务建立与幂等记录在同一私有事务内提交。账户行锁避免并发透支；全站模型成本仍使用原预算锁和独立成本账本。
- 任务结束、取消排队或恢复中断时，仅对 `complete` 且 `checks.passed=true` 的新谱行结算。失败、结构不通过、未开始或结果未知的行释放积分；供应商已经发生的成本仍保留，不因积分返还归零。
- 一行内部补救包含在该行费用中。主动重试须重新确认，仅冻结未完成行；已成功并复用的行不重复收费。
- 退回的冻结恢复到原批次，不延长有效期。跨过到期日的返还不能继续使用，界面事先告知。
- 运营可对已结算任务补偿实际扣除的积分，最多补一次，保存原因和审计；补偿长期有效，不会被原套餐到期吞掉。
- 旧版未使用的一次性任务奖励按每任务最多 30 行 × 5 = 150 积分转换一次，保留原奖励价值；旧版每月免费任务上限不会每月再赠送积分。后续邀请码奖励继续兼容旧奖励单位，每单位 150 积分。历史任务不追溯收费。

## 商户配置

仅在服务器环境变量配置以下参数。私钥与支付公钥文件放在仓库外的私有目录，运行账户可读；不要上传到曲库、前端或提交进 Git。现有启动脚本读取进程环境，不自动加载 `.env` 文件。

公共配置：`QINBAN_PUBLIC_ORIGIN=https://你的域名`，须为没有路径或末尾斜线的 HTTPS origin。对外 HTTPS 反向代理到商业版，并保留两个支付回调路径。生产账号运行时还须满足原有数据库、邮箱和密钥配置。

| 微信环境变量 | 内容 |
| --- | --- |
| `QINBAN_WECHAT_APP_ID` | 与商户号绑定的 AppID |
| `QINBAN_WECHAT_MCH_ID` | 直连商户号，须开通 Native 支付 |
| `QINBAN_WECHAT_CERT_SERIAL` | 商户 API 证书序列号，用于请求签名 |
| `QINBAN_WECHAT_PRIVATE_KEY_FILE` | 商户 API RSA 私钥 PEM 路径 |
| `QINBAN_WECHAT_API_V3_KEY` | 32 字节 APIv3 密钥，用于回调解密 |
| `QINBAN_WECHAT_PUBLIC_KEY_ID` | 微信支付公钥 ID，须与回调／应答 `Wechatpay-Serial` 相符 |
| `QINBAN_WECHAT_PUBLIC_KEY_FILE` | 微信支付公钥 PEM 路径 |

微信使用公钥模式，公钥轮换需要同步更新 ID 和文件。生产下单、查单与回调均验签；回调另做 AES-256-GCM 解密，核对 AppID、商户号、订单号、CNY 金额和流水。

| 支付宝环境变量 | 内容 |
| --- | --- |
| `QINBAN_ALIPAY_APP_ID` | 支付宝应用 ID，须有扫码收款权限 |
| `QINBAN_ALIPAY_SELLER_ID` | 实际收款卖家 UID |
| `QINBAN_ALIPAY_PRIVATE_KEY_FILE` | 应用 RSA 私钥 PEM 路径，支持 PKCS1／PKCS8 |
| `QINBAN_ALIPAY_PUBLIC_KEY_FILE` | 支付宝公钥 PEM 路径，不是应用公钥 |

支付宝使用官方 `alipay-sdk@4.14.0` 的 API v3 下单和查单（默认响应验签），通知使用 RSA2 验签与单次表单解码，核对 AppID、卖家、订单、金额和交易状态。当前只实现普通公钥模式。

任一渠道配置不完整时仅禁用该渠道；不生成演示收款码、不模拟支付成功。配置了不可读文件时启动报错，便于定位部署问题。测试注入的网关只能从服务端构造参数传入，HTTP 不提供启用模拟支付或标记已付款的接口。

## 数据迁移与接口

本地 PGlite 启动自动应用新增的 `db/0004-accounts-subscriptions-v1.sql`；生产须使用维护凭据在现有控制库应用该迁移。不要把账号／私有库运行账户提升为表所有者。迁移只新增表和权限，不删除已有数据。

| 接口 | 作用 |
| --- | --- |
| `GET /api/v1/subscriptions/catalog` | 公开套餐、规则版本、支付渠道可用状态，无商户密钥 |
| `GET /api/v1/operator/payments` | 运营账号查看最近 100 笔支付订单元数据 |
| `GET /api/v1/subscriptions` | 当前账号积分、有效期、最近 50 订单与 100 条账本事件 |
| `POST /api/v1/subscriptions/orders` | 按产品 ID 和渠道建订单，要求会话、CSRF、幂等键 |
| `GET /api/v1/subscriptions/orders/:id` | 仅订单所属账号可读 |
| `POST /api/v1/subscriptions/orders/:id/checkout` | 恢复未生成二维码的原订单，继续使用同一商户订单号 |
| `POST /api/v1/subscriptions/orders/:id/refresh` | 所属账号主动查单，持久化 10 秒限频 |
| `POST /api/v1/payments/notify/wechat` | 微信回调，原始 JSON，验签成功且入账提交后返回 204 |
| `POST /api/v1/payments/notify/alipay` | 支付宝回调，表单数据，成功提交后返回纯文本 `success` |

仅这两个 POST 回调免会话和 CSRF，依靠支付平台签名认证；其余写接口保留原认证、同源限制。通知最大 64 KiB。重复通知、查询与通知同时到达都只发放一份权益；交易流水不能用于两个订单。网络中断继续使用同一商户订单号，且无“前端跳转即成功”的入账路径。

二维码有效期约 30 分钟；过期不代表付款绝不会成功，迟到的有效付款通知仍按原订单兑现。查单失败保留待确认状态并提示不要重复付款。服务器重启保留订单、冻结、积分和周期；用户可从自己的订单页恢复。现金退款目前由商户核对处理，没有自动退款接口；积分补偿不会伪装成支付退款。

## 验收与上线边界

自动验证覆盖：价格篡改、订单隔离、CSRF、伪造及重复回调、错误金额／商户／流水、RSA2 和微信签名及 GCM 解密、补查入账、周期与到期、积分并发、取消与失败返还、部分成功重试、运营补偿和前端确认流程。

仍需实际商户环境验收：正式域名 HTTPS 回调可达性、应用产品权限、真实扫码与查单、小额订单到账、重启后回调补投，以及供应商的真实模型费用。完成配置和联调前，不能把代码接入视为已开通收款。

接口依据：[微信 Native 下单](https://pay.wechatpay.cn/doc/v3/merchant/4012791877)、[微信支付公钥验签](https://pay.wechatpay.cn/doc/v3/merchant/4013053249)、[回调解密](https://pay.wechatpay.cn/doc/v3/partner/4012082320)、[支付宝官方 Node SDK](https://github.com/alipay/alipay-sdk-nodejs-all)。
