# 升降号增强识谱策略

当前提示词版本为 `piano-recognition-p0-v7-20261028`，原文位于 `lib/recognition-prompts.mjs`。单图和整谱谱行共用这份规则；请求固定为 `gpt-6.1-sol` / `high`，不回退到本机 OMR。

先以谱号和音头线间位置确定音名字母、八度，再按调号和临时记号计算 MIDI。逐谱表、逐小节维护临时记号状态，区分降号、还原号、重升降、跨小节延音及和弦中错位排列的记号。更换提示词会使旧版识别缓存失效；文件版本并不构成准确率保证。

五首原谱的入口是 `npm run scores:reread-five`。默认只检查原始 PDF、全部 30 页和 143 行图片，不调用模型。加 `--run` 后新建或恢复本批任务：先让首行实际识读成功，再继续整批。只复用本轮已完成的检查点，不把历史版本的音符答案交给模型。

运行器默认 16 路滚动请求，可用 `--concurrency` 调整，最大 100。超时或取消的请求在真实退出前仍占用物理并发槽，避免旧请求尚未结束就发出替代请求。

五本谱先共同进入滚动队列，某一本的慢行不会阻塞其余书目的发起。对具体字段或结构校验失败，提交工具返回音符/小节位置，最多补救一次。Pi 工具补救与数字 JSON 回退共享“首读加一次补救”的两次请求上限；已用完补救时不再启动第三次回退。逐行本地结构检查在接收提交时执行。该输出保留音高、节奏、声部和延音，缺少原谱音头坐标时不补造坐标，导入后使用重绘数字谱跟随；原图用于对照。

正式 PDF 和五首批量入口默认执行首次识别，每条完整双手谱行正常调用一次模型，已移除第二轮 AI 独立复核及其重试入口。旧任务中的 `verify: true` 不再启用复核。具体校验错误可有一次补救，明确拒识、限流和认证错误不自动补救；用户主动重试另记调用；历史校对结果和手动音符编辑保留。AI 草稿不会标为人工确认。

逐小节是同一次整行请求内的阅读顺序，用来维护临时记号、拍数和延音，不能把它误算成每小节一次 API 调用。正常 N 行从 2N 次降至 N 次；并行、输出长度和服务延迟使实际耗时不一定减半。

速度上下文与音符读取分开。原谱未印、不可辨或未知时，compact-v4 接受 bpm=null，旧响应的0也按未知保留。tempoEvidence 保存原始值与状态，score.tempo 是可编辑练习速度；缺少上下文时使用90或用户练习设置。整谱组装只用首行初始速度与明确变速事件，不把每行的默认值当作新的印刷速度。不因缺少速度而拒绝读取音符，也不把先前练习设置当作原谱速度。

模型原始回答、调用时间、实际请求模型/思考档位、提示词版本、用量和续跑凭据保存在私有 `.local/batch-five-high-accidentals-v2/`。输出中的缺行和结构失败必须可见。导入不等于人工逐音确认；没有独立真值时不能自报全谱准确率。

`--import` 需要整批完整返回并通过本地结构检查，写入曲库时保留旧版并标注 AI 待校对状态。`--publish` 再推送曲库。凭据、私有任务状态、用量原始日志和原始谱图不进入 Git。

倚音、延长记号和变速使用独立于纸面拍位的演奏时间轴，数据约定和借时默认值见 [演奏时间轴设计](expressive-timing.md)。

P0 的离线回归与交付记录见 [识谱 P0 实施与验证](recognition-p0-implementation-20261028.md)。原谱升降号规则仍为 `accidentals-v2-20261018`，输出协议为 `compact-v4`，复用缓存为 `reviewed-source-v3-p0`；这些组件版本不要求与整体提示词版本相同。

完整谱行的原始提交、结构疑点及补救结果保存在任务的 `recognitionAttempts` 与私有 `recognition-usage.jsonl.submissions.jsonl`；usage 记录单独统计实际请求、字段报告次数和缺失。托管补救须再次通过预算预留，数据库升级先执行 `accounts-recognition-p0.sql`，保留首读账目。
