## 统一读取与验收

单图先确定完整双谱表系统行范围，再使用与整谱相同的谱行读取、接收、校验和组装模块。只处理所选图片不等于证明原书完整；范围确认、人工逐行审核和曲库写入仍是独立步骤。GPT 入口固定 `gpt-6.1-sol` / `high`，不启动本机 OMR 生成音符；已有 DeepSeek 入口继续使用相同契约。

新提交必须同时提供 MIDI 事件和 `notation`：原谱字母/八度/有效升降值、显式临时记号、谱表、谱号变化、独立声部活动区间和显式休止。音头线间位置可选，有值时检查与谱号是否一致。手别、声部、原谱谱表和输出谱表各自保留。旧 MIDI 格式仅用于历史兼容，不从 MIDI 反推纸面音名后标为新识别。

先由原谱拼写和八度移位推导发声音高，再与模型 MIDI 比较。临时记号状态按小节、谱表、字母、八度维护，同拍事件先成组再更新；矛盾保留两种读数，等待按原图裁决，不自动移动音符。真正跨小节延音不把临时记号状态带入新小节。

逐声部区间必须由原谱音符或显式休止解释。排版推断的休止不能消除缺口；一个声部的长音不能掩盖另一声部漏掉的时值。和弦音虽可同时覆盖时间，仍可能漏音，结构通过不能证明视觉识别完全正确。

速度上下文与音符读取分开。`bpm=null`（兼容旧响应的 0）保存为未知、不可辨或未标速；`tempoEvidence` 保留原始状态，`score.tempo` 是可编辑练习速度。缺少上下文时使用 90 或用户练习设置，不把每行的练习默认值写成印刷变速。

## 原图上下文与有界恢复

整谱首次读取附加原 PDF 首个有效谱行所在页的抬头/开头区域，仅供读取谱号、调拍号、速度或连音约定；后续单图系统附加原图开头上下文。模型被明确要求只输出目标谱行，不计入上下文里的音符。原始图像、上下文和重渲染图的哈希分别保留。

本机 `recognitionPlan` 默认 `{review:'off', maxCalls:2, recover:true}`：正常每行一次首读；有明确数据/覆盖问题或可恢复拒识时，将剩余一次预算用于本行恢复。PDF 从原文件更高分辨率渲染，并提供保留完整双谱表的重叠细节图；位图仅使用原始像素裁切，不声称放大恢复了细节。

本机可显式设置 1–6 次总调用预算。只有提供 `measureBoundsVerified:true` 和已核对、连续的完整小节边界时，才允许继续分为两个小节组；切分保留原行及首部上下文、重叠区和父区域映射。合并保留重复音、同音多声部及独立事件身份，不按 MIDI 去重；上下文区混入的事件不能自动接纳。默认两次预算不会额外启动分段调用。

请求前后写入检查点。成功行不重读；请求状态未知时不自动再次派发。格式补救、原图恢复、分段和复读共享本行总预算。限流、认证失败或未完成的服务请求停止自动恢复。失败的图像准备仍保留首读可编辑候选；预算耗尽后保留原始提交和具体疑点。

托管任务最多两次调用。第二个槽位可用于结构补救、原 PDF 高清恢复或明确开启的独立风险复读，每次均重新报价、预留和结算，保留已有订阅及积分逻辑。P1 不增加数据库调用次数上限；P0 数据库迁移仍须已完成。

## 独立风险复读

默认关闭。整谱设置可勾选“复读高风险谱行（实验，可能增加一次调用）”，或提交 `recognitionPlan.review='risk'`。候选信号包括多升降调号、密集音头、较多显式临时记号、换谱号、八度线、结构矛盾及模型警告；这些是未经校准的启发规则，不是正确概率。

在剩余预算内，仅复读触发的目标谱行，保持原模型和档位。第二次请求只获得原图及读取规范，不获得首轮音符答案；先保存独立输出，再比较发声事件、原谱拼写、显式记号、谱号、休止、声部划分和延音。声部编号改名本身不算分歧。

分歧不覆盖首读、不自动投票；保存两次结果，须按原图修改并明确人工审核。结果一致也不替代原图校对。尚无足够的固定预算、未触发区域抽查与作品保留集结果证明增量收益，因此本轮保持实验选项，不启用默认复读。

## 校对、导出和兼容

校对界面可修改原谱音名、显式记号、原谱谱表、八度移位、谱号/调号变化、休止与声部区间；有原图坐标的休止显示标记。修改来源证据不会静默改动 MIDI，需同时核对冲突。明确删除事件会清除其来源引用和失效延音，保留修改记录；新增音符没有猜测的纸面音名。

新转录的音头、`tieTo`、显式休止与来源证据经琴伴 JSON/MusicXML 保存和回读；MusicXML 使用原生音符、休止与谱表。原谱起始及小节边界谱号写入 App MusicXML，小节中途的谱号变化仍保存在证据并提示编辑器处理；Skill 以标准双谱表重排并展开八度记号。完整原样排版及所有演奏符号不属于本轮保证。

App→Skill 转换不自动设置 checked/reviewed，也不补签原图复核证据。未支持的独立谱表调号、倚音细节或未知调式继续阻塞正式完成。旧成果、历史任务、人工编辑和旧评测不回写。

## 运行、评测和私有记录

五首历史批量入口仍为 `npm run scores:reread-five`，默认只检查全部 30 页原始范围，不调用模型。`--run` 新建或恢复当前提示词版本的独立批次，先通过一次真实首行读取再继续；默认 16 路滚动并发，上限 100，物理请求结束前不释放槽位。历史目录、旧提示词检查点和已确认结果不能冒充本轮首读，需用新的 `--out` 目录。

P1 的两行开发回归入口为：

```sh
node scripts/benchmark-recognition-p1.mjs BENCHMARK_ROOT NEW_OUTPUT --with-context
# 明确执行时再加 --run；每行一次，总上限两次，无补救或独立复读。
```

独立参考只在响应冻结后载入评分器。失败、拒识和未知 usage 保留；参考没有覆盖的书写记号不报准确率。开发样例、自动化测试和保存回读分别说明其证明范围，不将两行事件匹配外推为任意全谱正确率。

原始模型提交、局部恢复检查点、用量及图像只保存在私有 `.local/`；缺失 usage 写未知，不把 SDK 在失败时返回的全零占位计作真实零消耗。`--import`、`--publish` 仍分别要求完整性、范围与发布授权，不公开私有原谱、原始证据或凭据。演奏时间轴另见 [演奏时间轴设计](expressive-timing.md)。

## P2 固定回归与发布检查

当前组件版本来自 `lib/recognition-versions.mjs`；`recognition:versions` 检查 README、本策略、Skill 接入说明的当前标记，以及 Skill 元数据、包/锁文件与 Node/CI 配置。历史报告的版本不回写，也不把升降规则版本等同于整体提示词版本。

`npm run check` 同时执行 `recognition:release`，核对当前识别实现、模型输入文本/图像预处理指纹、固定来源/参考范围及已通过的回归证据。修改实现后重新回归；模型输入变化不能用旧响应的离线重放证明新视觉效果。回归集版本绑定来源、事件单位、参考层级、对齐方式、分母和运行范围，不能缩小分母后继续沿用同一版本。

固定语料和命令见 [P2 实施记录](reports/recognition-p2-implementation-20261028.md) 与 [语料登记](recognition-regression-corpus.json)。prepare/evaluate 均离线，既有失败、不完整和未知用量保留。真实读取须另选 `live` 并声明总调用预算；完整固定 PDF 范围目前需要至少 16 次预算，每行一次，不自动修复或复读。原图和参考不随源码发布，只有汇总、指纹与门禁结论进入 Git。

DeepSeek 在界面及策略中明确为实验 / 第二意见。当前 high 思考模式使用官方支持的 auto 工具选择；没有工具调用但返回单个完整 JSON 时，经同一提交校验接收，不为此额外发起请求；纯说明、截断、多工具调用或不完整 JSON 仍不能作为完成结果。此兼容处理没有被证明能提高真实读谱准确率。

用量分别保留实际返回字段与缺失：整个识别计划汇总首读、失败恢复、分段和复读，并按审计身份去重。托管结算继续要求有效输入/输出用量，缺失 total、缓存或思考字段不再补造。

可用 `node scripts/with-node.mjs check`、`... build` 或 `... launch` 选择本机兼容 Node；不修改全局 Node，CI 复用 .nvmrc。Skill 1.3 构建先暂存、校验并记录产物哈希，再发布完整目录；失败保留暂存并可显式 --resume，既有输出和被修改的文件不会被覆盖。
