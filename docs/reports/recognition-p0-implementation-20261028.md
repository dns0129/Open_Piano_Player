# 识谱 P0 实施与验证

日期：2026-10-28。依据：[识谱准确度提升融合报告](recognition-accuracy-integrated-report-20261028.md)。本轮完成 P0 的代码、数据契约和离线验证，未进行新的付费模型识图或线上服务验证。

## 已完成的行为

| P0 工作 | 实现结果 | 验证证据 |
|---|---|---|
| 冻结评测基线 | 原谱裁图、独立参考、任务映射、原始响应与历史结果均绑定哈希；重放不覆盖原目录 | 16 行、1292 个参考音；输入变化和重复写入会被拒绝 |
| 保存未知速度成果 | `bpm=null` 和旧响应的 `0` 保留为未知；`tempoStatus` 区分未印、不可辨与未知；`tempoEvidence` 保存原始值，数值 `score.tempo` 用于练习 | 单图、逐行、JSON 回退、托管解码及数字谱保存测试；历史 102 音响应恢复 |
| 可定位的错误反馈 | 输出错误字段路径、音符 ID 或小节位置；接收提交时执行结构校验 | 非法引用、错误类型、越界音符、缺拍及补救测试 |
| 有界补救 | 默认首读一次；明确字段或结构错误最多补救一次。Pi 工具补救与 JSON 回退共享两次实际调用上限；不默认全谱复读 | 使用真实 Pi Agent 循环和模拟提供方验证第二次收到反馈，失败后没有第三次回退 |
| 保存失败证据 | 原始提交、错误、补救结果及提供方响应分开保存在私有日志或任务中；结构仍有疑点的结果可以保留供人工编辑 | 两次失败仍保留音符与疑点；不能标为检查通过 |
| 托管预算与账目 | 第二次请求重新报价并预留预算，原首读与补救分别结算；数据库最多允许同任务同谱行两条调用记录 | 两次调用分别计费；迁移保留原费用和 usage；第三条调用被拒绝 |
| 严格复核字段 | Skill 的 `checked`、`reviewed`、`complete`、`humanConfirmed` 必须为布尔值 | 字符串 `"false"`、`"true"` 和数字即使在草稿模式也会被拒绝 |
| 复核证据失效 | Skill 按小节绑定原图、转录内容与延音依赖；App 的代理批准绑定乐谱及来源摘要 | 删音、改音和来源变化使旧证据失效；独立小节可保留有效证据 |

程序不会把复核记录本身当作视觉准确率证明。生成记录的函数只保存执行者在真实原图核对之后的声明；旧记录没有绑定证据时，不自动补签为已确认。

## 离线重放结果

使用 2026-10-21 密集 PDF 评测中已存在的模型响应，完整保留失败行的参考分母。没有重读原图、修改原始音符或使用参考答案生成结果。

| 指标 | 原流程保留结果 | P0 离线重放 |
|---|---:|---:|
| 参考普通书写音符事件 | 1292 | 1292 |
| 保留的预测事件 | 833 | 935 |
| 严格匹配事件 | 831 | 933 |
| 严格事件召回 | 64.3% | 72.2% |
| 返回事件精确率 | 99.76% | 99.79% |
| 本轮新增模型调用 | — | 0 |

增量来自一条历史回退响应：102 个音符原本全部匹配参考，却因为 `bpm=0` 未被流程保留。P0 将其音符保存下来，同时保留速度未知状态。

这是结果恢复收益，不是模型视觉识别能力提高的证据。剩余拒识区域及两个 B♯ 错误没有被这次重构消除；书写音名、休止、演奏记号和新照片场景的准确率仍需后续独立评测。

## 验证环境与结果

本机默认 Node 21.3 不满足项目要求。本轮使用已有 Node 24.19.0，在基于主线 `7c91b39` 并仅叠加本轮文件的隔离源码快照中检查，未带入其他任务的未提交实验脚本。

- `npm run check`：类型检查、静态检查、格式检查通过；513 项测试中 511 项通过，0 项失败，2 项因可选私有原图样本未放入隔离快照而跳过。
- 曲库验证：60 首曲目通过。
- `npm run build`：生产构建通过；保留现有的大分块提示。
- Skill 自测：8 项通过，包括真实页图哈希、重新排版 SVG、严格布尔值、逐小节证据失效及未知速度草稿。
- Skill 元数据校验通过；本机安装目录与仓库本轮 10 个 Skill 文件逐个哈希一致，安装目录的 8 项自测通过。

测试使用模拟模型响应和隔离账户/曲库数据。没有因此改变真实用户的曲库、历史评测结果或模型凭据。

本机证据位于 `.local/recognition-p0-20261028/`：初始哈希、冻结评测清单、离线重放、隔离源码文件哈希、测试与构建日志，以及已安装 Skill 的更新前备份。该目录不进入 Git。

## 版本与兼容性

| 组件 | 当前版本或行为 |
|---|---|
| 整体提示词 | `piano-recognition-p0-v7-20261028` |
| 升降号专项规则 | 保留 `accidentals-v2-20261018` |
| 紧凑输出协议 | `compact-v4`，兼容旧速度 `0` 的未知含义 |
| 已复核来源缓存 | `reviewed-source-v3-p0`，旧缓存不冒充新版识别 |
| piano-score-to-musicxml Skill | `1.1.0` |

旧谱和旧复核记录保留。Skill 缺少新证据的文件仍可使用 `--draft` 导出检查；实际核对后再使用 `recordMeasureReview` 记录当前小节证据。未知或不可辨速度可保留草稿；明确确认原谱未印速度时使用 `not-marked`，练习速度不会冒充原谱数字。

App 的代理复核批准使用 `agentReviewBasis(job)` 绑定当前内容。没有有效绑定的旧批准回到待复核语义，不删除乐谱或历史证明。

## 托管数据库升级

新增迁移为 [0005-accounts-recognition-p0.sql](../../db/0005-accounts-recognition-p0.sql)。它为历史调用增加默认序号 1，保留原记录和费用，将唯一约束扩展为同任务、同谱行、同调用序号；序号只允许 1 或 2。

嵌入式数据库启动与显式迁移流程已包含该文件。外部 PostgreSQL 部署需在启动新托管识别代码前，通过现有维护凭据执行完整迁移流程；运行账号不应临时获得维护权限。本轮只在隔离数据库验证迁移，没有对云端数据库执行迁移或重启线上服务。

## 复现离线恢复检查

在 Node 24 环境中，使用已有原始评测目录和新的输出文件名：

```bash
node scripts/freeze-recognition-baseline.mjs \
  .local/dense-pdf-benchmark-20261021 \
  .local/p0-frozen-new.json

node scripts/replay-recognition-p0.mjs \
  .local/dense-pdf-benchmark-20261021 \
  .local/p0-replay-new \
  .local/p0-frozen-new.json
```

两个工具均为离线工具，不调用模型；已存在的冻结文件或输出目录拒绝覆盖。发布的源码不包含原谱、模型原始响应、独立参考文件或凭据。
