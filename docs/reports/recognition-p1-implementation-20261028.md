## 2. 核心数据与规则

`lib/recognition-notation.mjs` 是 App 的纯计算规则模块，独立副本随 Skill 分发。传输层 `notation` 以事件数组下标绑定证据，接收后转换为稳定 `noteId/restId`，保存于 `score.recognitionEvidence`。原谱谱表、演奏手别、声部与重排谱表独立保存。

发声音高按以下关系检查：

`MIDI = 12 × (writtenOctave + 1) + naturalSemitone(step) + alter + ottavaShift + clefOctaveChange × 12`

C/D/E/F/G/A/B 的自然半音分别为 0/2/4/5/7/9/11。例：B♯4 是 `60 + 11 + 1 = 72`，不能写成 70。模型 MIDI 与纸面推导不一致时记录 `PITCH_DISAGREEMENT`，保留两者，不静默改音。有效书写信息不等于看图一定正确。

临时记号按小节、谱表、字母和八度维护；同谱表跨声部共享，跨谱表和八度独立。同拍先收集显式记号再更新状态，数组换序不改变结论，冲突明确阻塞。跨小节真正延音保留连接音高，不污染新小节的临时记号状态。可选线间位置从谱表底线为 0 向上计步，检查与谱号、字母和八度是否一致。

逐声部校验共用于浏览器预检和服务端接收。新增音符必须明确填写原谱读数，不从 MIDI 自动补名；休止必须具有唯一来源引用。删除原谱事件后，遗留引用会阻塞接收；用户在界面明确删除时同步清理其来源/延音并保存修改记录。证据修改不会悄悄移动 MIDI。原谱休止有坐标时显示“休”标记，没有坐标时不补造位置。

## 3. 原图上下文与恢复策略

真实试验表明，中间谱行可能没有足以判断拍号、三连音省略规则的文字上下文。因此首读附加原 PDF 首个有效谱行所在页的抬头/开头区域；只读取谱号、调拍号、连音与速度约定，不计入该图音符。相同任务共用 PDF 和上下文渲染，避免逐行重复处理整页。后续单图系统也保留原始开头上下文。

默认策略为 `recognitionPlan={review:'off',maxCalls:2,recover:true}`：正常一行一次；发生可恢复拒识、覆盖或结构矛盾时，剩余一次用于该行恢复。PDF 从原文件重渲染并提供重叠细节；位图保持原始像素，不把插值放大当成新增信息。高清准备失败时保留已有可编辑候选。

本机可显式配置 1–6 次总调用预算。继续分段需要至少两次剩余预算，且只能使用 `measureBoundsVerified:true` 的连续完整小节边界。分段保留整行及首部上下文，记录图像哈希、选择区间、父区域映射；边缘重叠只能用于读取。合并保留每个事件的独立身份、重复音、显式休止、小节图、变速与跨段延音，不按相同 MIDI 去重。缺失边界、混入上下文音符或接续不明时停止自动拼接。

请求前先记录 pending，返回后保存结果或错误。恢复不重读已成功阶段，状态未知的物理请求不自动再次派发。每次首读、补救、分段与复读共用预算；限流、认证失败和未完成服务请求停止自动补救。原始提交、检查点、图像哈希、错误及实际 usage 私有留存。

托管队列保持最多两次调用，每次重新进行预算/积分预留与结算，保留既有商业逻辑。第二个槽位可用于格式补救、PDF 高清读取或显式开启的风险复读；不增加数据库的调用上限。

## 4. 独立复读与人工审核

整谱设置新增“复读高风险谱行（实验，可能增加一次调用）”。默认关闭；`review:'risk'` 时，以密集音头、调号数量、显式临时记号、谱号变化、八度线、警告和检查矛盾筛选目标谱行。这些规则没有被校准为真实正确概率。

第二次请求不包含首轮音符或此前答案。先冻结独立输出，再规范化声部划分并比较发声事件、源谱音名、显式记号、谱号、休止及延音。单纯声部编号改名不算错。分歧保留首读和第二次结果，不自动投票，不替用户确认；校对界面显示分歧，明确审核后记录人工裁决。两次一致也不能清除原有来源疑点。

本轮没有足够的未触发区域抽查、独立局部复读增量统计和作品保留集结果，不能据回归替身宣称复读提高了真实准确率。该收益实验完成前保持默认关闭，也不扩大为全谱第二遍调用。

## 5. 保存、导出与 Skill 1.2.0

新转录保留书写音头与原生 `tieTo`，不在保存时把延音音头合成一个不可追溯事件。琴伴 JSON、原生 MusicXML 和来源图保留原谱拼写、谱表、手别、显式休止与来源证据，回读不从音高重新猜纸面写法。MusicXML 使用原生音符、休止和谱表，证据 envelope 随标准 miscellaneous 字段保存。

Skill 升级到 1.2.0，新增 `notation.rests/clefs/voices`，严格复核类型继续生效；逐小节复核哈希绑定休止、谱号和声部范围，修改后相关复核失效。App→Skill 转换默认 `checked/reviewed/humanConfirmed=false`，有纸面音高矛盾即拒绝转换，不从历史 MIDI 伪造证据。

明确保留以下表达限制：

- App MusicXML 写入原谱起始及小节边界的谱号；小节中途谱号变化保存在证据，并提示用编辑器调整。
- Skill 采用标准双谱表重排、展开八度记号，原始谱号变化仍留在 transcription；不宣称原样复刻 8va 线和版式。
- 独立谱表调号、尚缺纸面信息的倚音和未知调式等在桥接时进入未支持/未解决清单，不能导出为正式完成。
- 全部演奏记号的视觉识别、手机照片保留集、整曲首尾覆盖和所有下游编辑器的扩展字段兼容性不由本轮两行样本保证。
