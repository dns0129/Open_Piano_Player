# 账号与私有曲库实现与本机验收

日期：2026-10-21。账号服务、数据库隔离与前端已实现；真实 PostgreSQL 服务、SMTP、HTTPS 和两台真实设备的联网验收尚未配置。它是可在本机使用和验证的账号版，不是已经上线的收费服务。

后续商业阶段已实现托管识谱、任务数与成本控制、手机上传和基本运营；入口迁至独立商业首页 `/`，练习室为 `/practice.html`，本页继续说明账号与数据部分。[商业版实现与运行](commercial-app-implementation.md) 和 [新增验收](commercial-app-validation-20261021.md) 记录本轮变化，旧账号目录与命令兼容。

## 启动与数据位置

需要 Node.js ≥22.19。macOS 启动器会选择可用的新版本 Node；终端中的 `node` 也需要符合版本要求。本机若只有旧版 Node，可先把已安装的新版本 Node 所在目录放到 PATH 前面，再运行 npm 命令。

```sh
npm run accounts:invite -- teacher@example.test
npm run build:hosted
npm run accounts:start
```

邀请命令应在账号服务停止时运行。数据库打开后有进程锁，避免两个本机实例同时写入嵌入式 PostgreSQL。也可先邀请，再双击仓库根目录的 `启动账号版.command`，它会构建并启动账号版。打开 `http://127.0.0.1:8793/account.html`，发送验证码后，到页面提示的开发邮箱目录读取本次验证码；该模式不投递真实邮件。

默认数据目录为 `.local/accounts-v1/`，受 Git 忽略：

- `postgres/`：PGlite 嵌入式 PostgreSQL，保存账号、会话和曲库元数据。RLS 使用真实 PostgreSQL 角色与策略执行。
- `private-files/`：以账号 UUID 和资源 UUID 分目录保存的私有原文件，目录 700、文件 600。
- `development-mailbox/`：仅本机验证的开发邮件；含测试验证码，不经 HTTP 提供，不进 Git。
- `secret`、`runtime.lock`：本机密钥及单实例锁。迁移本机账号数据时必须妥善保留密钥，否则旧会话和验证码无法继续验证。

`QINBAN_ACCOUNT_DIR` 可以指定独立数据目录；`QINBAN_ACCOUNT_PORT` 可更改端口。关闭服务用启动终端的 Control+C。原 `启动琴伴.command` 和 8792 服务继续使用旧曲库，不自动切换存储。

## 已可使用的流程

1. 受邀邮箱通过 8 位验证码登录。验证码 10 分钟有效、最多尝试 5 次；发送、验证限流和一次性消费存于数据库。未知邮箱不自动创建账号。邮件投递失败使验证码失效。
2. 账号页面导入 MusicXML、MXL、MIDI、琴伴 JSON，保存后进入现有练习室播放、编辑与另存修改版。保存使用服务端修订号；并发改动返回冲突，不覆盖新版本。
3. 上传 JPEG、PNG、WebP 前确认页序；每张最多 20 MiB、40 百万像素，每组最多 6 张。原字节保留，EXIF 或手工旋转生成独立派生图。PDF 最多 50 MiB、6 页，保存完整页序和原始文件。保存原图、PDF 本身不会调用识谱模型。
4. 原始资料独立于数字谱持久保存，可下载、备份；未关联任何历史修订的资料组可主动删除，文件延迟清理。新拍摄图片不必先识别成功才能保存。
5. 历史恢复生成新修订。移到回收站后保留 30 天，可在账号页面恢复。设备会话可逐一撤销；完整备份、退出所有设备和注销要求 10 分钟内的邮箱验证。
6. 注销后立即退出全部设备，等待期 30 天。等待期内通过原邮箱取得受限恢复会话，恢复成功签发新会话，旧恢复会话失效。到期清理先锁定为 deleting，防止恢复与清理竞争。
7. 完整备份 v2 包含数字谱、历史、原文件、原图及单独保存的资料组，校验规范化 JSON 摘要与每个原文件 SHA-256。导入前预览目标账号、重复项和冲突，可跳过、另存副本或明确替换预览中的修订；同一导入重试不重复创建已成功项。重复判断包括原文件与历史，不能仅以音符相同跳过不同的原谱。
8. 本机验证入口允许主动勾选旧本机曲目，导出后再预览导入账号。旧目录保留。游客浏览器曲库可先从旧版导出备份，再在账号页恢复；登录不会自动上传游客数据。

账号页负责备份恢复、回收站和历史管理，练习室对应入口会带回账号页。私有曲谱和图片只作内存缓存；切换账号或撤销会话后，播放器、谱面、原图 URL、编辑窗口与账号缓存清空，旧响应和旧文件上传被拒绝。localStorage 仅保留显示偏好，旧识谱恢复凭据不迁入账号版。

## 数据和权限的实现

`lib/accounts/identity.mjs` 集中处理身份；`private-library.mjs` 处理所属关系、文件接入和修订；`transfers.mjs` 处理完整备份和导入回执。HTTP 层不接受客户端指定 owner，资源下载必须通过本人会话。私有表统一 FORCE RLS，关联资源使用 `(owner_id, id)` 外键，应用侧同时限定 owner。跨账号对象统一返回 404。

`db/accounts-v1.sql` 是维护凭据执行的初始化 SQL。身份表位于 qinban_identity，曲库表位于 qinban_private；运行时身份角色与曲库角色分开，均不拥有表，也不能绕过 RLS。本机嵌入式数据库在事务中切换到对应非特权角色；正式连接适配器使用两个受限连接池，并拒绝超级用户、RLS bypass、表所有者和相互继承权限的配置。

上传先预留容量，核对实际字节、SHA 和解码后的类型，再成为可引用资源。默认每账号 1 GiB；原图、派生图、历史、回收站、备份和暂存预留均参与容量限制。对象采用临时文件和原子重命名；定时维护清理过期暂存、导出、回执及无引用对象，孤立文件延迟一天并再次查库后回收。显式保存的来源组不会因尚无数字谱而被自动回收。

本机账号接口只监听回环地址。正式模式要求 HTTPS 来源、Secure HttpOnly `__Host-` Cookie、CSRF、同源校验和受限的回环反向代理（须追加 `X-Forwarded-For`，如 nginx 的 `$proxy_add_x_forwarded_for`；验证码按其中最后一个地址限流）；旧模型设置、GitHub 发布、网易登录和原始 `.local` 文件均不暴露。完整备份下载同样要求本人会话及近期验证。

## 验证证据与边界

自动化测试覆盖账号验证失败、过期与重放，真实 PostgreSQL RLS，A/B 账号交叉访问，CAS 并发保存，幂等重试，原始图片/PDF 哈希，EXIF 派生关系，来源页序，历史和回收站，完整备份与恢复，导入冲突，到期清理，以及关闭再打开数据库后的账号、会话、修订和原文件读回。HTTP 测试覆盖 Cookie、CSRF、Origin、会话撤销、旧本机接口拒绝，以及切换身份时的晚到数据和文件上传。

全量检查命令为 `npm run check`；三种构建分别为 `npm run build`、`npm run build:pages` 和 `npm run build:hosted`。具体最终计数、浏览器验收结果与原数据保全核对见 [本轮验收记录](account-private-library-validation-20261021.md)。图片识谱的独立报告见 [24 张照片测试](phone-score-accuracy-20261021.md)，存储和播放测试不代替逐音准确性证明。

账号页面使用分页元数据接口；为兼容现有练习室，hosted Adapter 会读取曲谱文档投影，列表阶段不下载原图和原文件。大量曲目时的文档懒加载和分页管理仍可优化。来源资料列表目前返回最近 100 组，账号页显示当前列表最多 100 首；完整备份覆盖全部未回收曲目及全部固定来源组。

## 正式接入前仍需完成

正式配置使用 `QINBAN_ACCOUNT_PROFILE=production`、`QINBAN_PUBLIC_ORIGIN`、`QINBAN_ACCOUNT_SECRET`、`QINBAN_AUTH_DATABASE_URL`、`QINBAN_LIBRARY_DATABASE_URL`、`QINBAN_SMTP_URL` 和 `QINBAN_MAIL_FROM`。密钥只放服务器配置；运行时不自动用管理员身份迁移数据库。先以独立维护身份依次执行 `db/accounts-v1.sql` 和增量 `db/accounts-commerce-v1.sql`，再建立分别继承 qinban_identity / qinban_library 的两个 LOGIN 角色，运行账户不能同时继承另一角色，也不能拥有表。

当前文件 Adapter 是服务器私有文件目录，正式部署必须配置持久卷、数据库与文件的一致备份和恢复演练；尚未接入 S3 等外部对象存储。还需实际完成 PostgreSQL 服务连接、真实邮件、域名与 TLS、反向代理、付费模型、多设备切换与权限传播验收。支付与教师分享尚未实现。本机验收不能代替这些部署证据。
