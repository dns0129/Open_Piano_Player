# 识谱准确度提升融合报告

日期：2026-10-28。范围：琴伴 App 识谱流程与 piano-score-to-musicxml Skill。状态：改进方案，尚未实施或开展新的模型评测。

## 一、结论与目标

准确度提升应围绕四件事展开：保留并检查视觉读谱依据，减少整行失败与漏音，针对疑点局部重读，以及用独立参考验证实际收益。App 负责的模型调用与 Skill 负责的转录校验应使用兼容的数据契约，使原谱信息从读取到导出始终可追溯。

优先顺序为：建立固定评测基线，同时修复错误拒收和错误完成状态；然后统一结构化音高、谱号、声部和休止信息；最后验证局部重试及高风险复读的收益。保留默认单次首读，不自动对全部乐谱再读一遍。

必须分别报告三类效果：

| 改进类型 | 主要解决的问题 | 对应验收方式 |
|---|---|---|
| 视觉与音乐识别改善 | 错音、错节奏、升降号或谱号误读 | 固定独立参考上的错误数量与召回变化 |
| 结果恢复与覆盖改善 | 拒识、格式失败、速度未知导致整行丢弃 | 恢复后的正确事件数、失败行和缺失范围 |
| 质量控制改善 | 错误结果被标为完成、复核证据过期 | 错误放行比例、证据有效性、疑点检出与误报 |

通过类型检查、保存更多结果或增加复核标记，本身不等于模型看图能力提升。新方案必须说明改善发生在哪一层。

## 二、已有证据与适用边界

原建议来自两部分：仓库的[识谱模型与规则检查及提升报告](recognition-improvement-report-20261028.md)，以及本聊天中对 Skill 文档、转换器和边界行为的审查。本报告复查了当前仓库相关协议与 Skill 校验源码；代码检查基线为 `81e3fb4`。

| 证据 | 可以支持的判断 | 不能据此推导的结论 |
|---|---|---|
| 密集 PDF：3 页、16 行、1292 个参考事件，严格召回 831/1292＝64.3%，返回事件精确率 831/833＝99.8% | 返回音符较准，但缺失行明显损害整体覆盖 | 所有复杂钢琴谱都达到 99.8% 准确率 |
| 同一评测：一行回退结果的 102 个音符匹配参考，但 `bpm=0` 导致校验失败 | 未知速度与音符成果应分别处理 | 修改速度策略后，新模型调用一定返回相同结果 |
| 同一评测：两处 B♯4 被读为 MIDI 70，参考为 72 | 需针对书写音名、线间位置、升降号建立回归样例 | 增加算术检查即可发现全部错音 |
| 手机整照：24 张中 6 张结构返回完整；独立参考仅覆盖两张照片的 3 小节、36 音 | 多系统整照仍存在覆盖问题，逐音参考范围有限 | 6 张照片全部音符正确，或其余全部错误 |
| 单系统补测：一张照片的一行返回 48 音，其中两个已冻结参考小节的 16 音全部一致 | 保留完整双谱表的区域读取值得扩大验证 | 16 个系统全部正确，或照片识别普遍达到 100% |
| 此前 Skill 边界检查：复核字段为字符串 `"false"` 仍通过；删除一个主音及其证据后仍无阻塞 | 复核字段类型不严；结构一致性不足以识别该漏音 | Skill 能仅凭时间轴证明原谱没有漏音 |

密集 PDF 数据来自[独立评测报告](dense-pdf-benchmark-20261021.md)。手机数据来自[手机实拍报告](phone-score-accuracy-20261021.md)，其视觉参考由代理在查看识别答案前冻结，未经人工逐音确认，应单独列为参考等级。两次模型读取的一致率只作为分歧分析，不纳入独立真值准确率。

## 三、统一的数据与识别流程

建议流程为：原始谱页与来源清单 → 完整双谱表区域和上下文 → 首轮视觉读取 → 原始响应保存 → 结构化证据与确定性校验 → 局部补救或复读 → 对照原图裁决 → 版本化转录 → 导出回读与结果报告。

App 和 Skill 共用核心转录语义，允许传输格式不同。转换过程必须保留字段含义与来源；旧缓存只有确实具备新字段时才能升级，缺失信息标为未知，不能从旧 MIDI 反推后冒充原图识别结果。

建议每个音至少保留以下信息：

| 数据 | 用途 |
|---|---|
| 稳定事件 ID、原页、系统行、小节、图像区域与原图哈希 | 定位、去重、局部修改与追溯 |
| 原谱谱表、谱号及变化、音头线间位置或书写字母与八度 | 核实音高读取依据 |
| 原谱显式记号、有效升降值、八度移位 | 区分“图上有什么”和“实际发什么音” |
| 模型给出的 MIDI、本地推导 MIDI、矛盾记录 | 检查计算与字段关系 |
| 起拍、符值、附点、连音组、延音目标、声部 | 保留纸面节奏与复音结构 |
| 原谱谱表、音乐声部、演奏手别、输出谱表的独立字段 | 避免交叉谱表或手别推断改变识别事实 |
| 字段状态与证据来源 | 区分已读取、未知、冲突和已复核 |

线间位置与书写音名之间宜有明确的派生关系，避免要求模型重复填写大量互相冲突的字段。可以先验证“书写字母＋八度＋显式记号”方案，再用实验判断额外线间坐标是否值得其输出成本。

## 四、P0 建立评测基线并修复错误拒收和放行

### 1. 先冻结评测条件与参考

在修改提示词和输出协议前固定输入、系统行范围、评分规则及独立参考。已有密集 PDF 样本可以作为回归基础；其旧评分没有覆盖等音拼写和全部演奏记号，需要补充参考后才能评价这些维度。

历史《幻听》、前奏曲、BWV846 等样本可以作为候选，先核实参考来源、版本、覆盖范围和是否参与过调试。模型复读一致的样本不能直接升级为金标准。将开发集与保留集按作品或版本划分，避免同曲近似谱页跨集合泄漏。

验收：每个评分数字都有明确分母与参考等级；失败行仍留在分母；独立参考不进入识别请求。

### 2. 未知速度不丢弃已读音符

允许保存 `tempo: unknown` 的转录结果。将原谱速度与练习播放速度分开：原谱明确未标速度、图像读不清、尚未读取是不同状态。没有新速度记号且上下文连续时，播放可沿用此前有效速度；上下文不确定时继续保留未知。首段需要预览时可使用标明来源的练习默认速度，例如 90 BPM。

速度缺失只限制相应完成声明或原速播放验证，不应清空已经读取的音符。保留原始 `bpm=0` 响应，归一化时记录“未知”的转换理由。

验收：用历史 102 音响应做离线重放，确认音符可保存且没有被修改；恢复收益单列，不能回写旧评测或当作新的视觉识别提升。

### 3. 返回具体错误并进行有界补救

把统一的“格式无效”拆成字段类型错误、引用不存在、拍位越界、时值矛盾、疑似覆盖缺口等，并标明事件 ID、字段路径和小节位置。

格式和算术错误可在提交工具内返回模型。对音乐结构疑点提供原图区域与问题描述，不提供臆造答案；不能要求模型用补音或补休止凑满拍数。初始方案允许最多一次自动补救，并在策略中记录调用预算；预算用尽后保存部分结果和疑点。

验收：原始响应、错误、补救响应和修改差异全部保留；分别统计修复成功、新增错误和额外调用成本。

### 4. 严格复核字段与证据状态

`checked`、`reviewed`、`complete` 必须严格为布尔值。字符串、数字等错误类型直接拒绝，不做真值转换。

复核记录关联原图区域、转录版本、具体字段、复核方式、时间和裁决。修改音高、节奏或引用来源后，受影响的复核结论失效；临时记号修改还应使同小节相关后续音、延音目标等依赖项重新进入核对。

验收：字符串 `"false"` 无法通过；修改已确认事件后不会沿用过期完成状态。该项提升质量控制可靠性，不直接计为读谱准确率收益。

## 五、P1 让音高与完整性规则可执行

### 5. 结构化音高与临时记号计算

先根据当前谱号和音头位置确定原谱字母与八度，再结合调号、显式临时记号、八度移位及真正的延音关系计算实际音高。

计算使用 `MIDI = 12 × (octave + 1) + naturalSemitone(step) + alter`，其中 C、D、E、F、G、A、B 分别对应 0、2、4、5、7、9、11；八度移位另行应用并保留原谱写法。降 B 与升 A 的发声音高可以相同，书写识别应分别计分。

临时记号状态按谱表、字母、八度和小节维护；同谱表跨声部影响、还原号、提示性记号、换谱号及跨小节延音分别测试。同时发生的相关事件不能仅依赖数组先后顺序更新状态，冲突应明确记录。

模型 MIDI 与本地推导不一致时形成疑点，回到原图裁决。不得静默用其中一个覆盖另一个，也不得用和声合理性自动修改原谱。

验收：覆盖 B♯、C♭、重升重降、同小节沿用、跨声部、跨八度、跨小节延音及换谱号；独立评测同时检查书写音名和发声音高。规则保证给定输入下的计算一致性，无法单独证明视觉输入正确。

### 6. 显式休止与逐声部覆盖

App 紧凑协议已有休止字段，Skill 主要以音符间隙表达休止。应统一保留带原谱证据的休止事件，包含声部、符值、拍位和来源。尚未解释的空缺保持为缺口，不能自动当作已确认休止。

逐声部检查小节时间区间、弱起、末尾休止、连音和延音。和弦内音符同时占据时间，不能把所有音符时值简单相加。共享音头、多声部和交叉谱表使用明确关联；不能为消除重叠提示而强行合并声部。

增加原谱与转录的区域对照，显示音符、休止、未解释位置及修改记录。即使时值全部覆盖，仍可能漏掉和弦中的一个音，因此还需原图核对和独立参考。

验收：删除音符后产生的空缺不会自动变为已确认休止；删除和弦音的样例也进入视觉与评分回归，不能只验证时间轴。

### 7. 统一单图与整谱入口

单图和整谱共享核心转录契约、校验及音高规则；单图先明确其包含的系统行范围，再使用同一套处理逻辑。接口响应不能因入口不同丢失声部、休止、延音或原谱拼写。

旧格式通过有版本的适配器过渡。确认没有生产调用且完成兼容性测试后，再移除旧定义。缓存键包含图像及裁切哈希、模型与档位、提示词组件版本和输出协议版本；保留旧成果，避免用缺字段的旧缓存冒充新协议输出。

验收：同一谱行经两个入口后，其音乐事件和证据语义一致；差异能够定位到明确的转换步骤。

## 六、P1 以局部重试和独立复读处理难例

### 8. 按失败原因选择局部处理方式

| 情况 | 优先处理 | 停止或转人工条件 |
|---|---|---|
| PDF 细节不足 | 从原 PDF 更高分辨率重渲染目标区域，保留上下谱表与必要上下文 | 原始内容仍不可辨 |
| 手机照片模糊、透视或遮挡 | 保留原图，提供可追溯的局部裁切或几何校正 | 原信息缺失，需要新照片 |
| 密集行拒识或输出过长 | 按完整小节分段，保留重叠和跨段上下文 | 剩余范围仍无法可靠读取 |
| 数据结构或算术错误 | 返回具体错误，执行一次有界补救 | 同类错误持续存在 |
| 限流或超时 | 保存任务状态，确认旧请求结束后再决定续跑 | 无法判断旧请求状态或预算耗尽 |

放大低清位图不等于恢复细节。重叠裁切的结果按来源小节、图像位置和事件身份合并，不能仅凭相同音高去重，以免删除重复音或同音多声部。

模型和思考档位默认保持用户指定配置。提高档位只能在明确允许的策略与预算中作为独立实验，收益与图像处理收益分别统计。

验收：成功行不重复请求；失败行恢复后不丢音、不重复音；每次重试保留输入、结果、原因、耗时和实际 usage。

### 9. 高风险区域复读作为待验证策略

候选触发信号包括较多升降号、密集临时记号、换谱号、八度线、跨行延音、异常覆盖、模型警告和字段矛盾。调号数量等阈值在开发集上选择后固定，不能一边看保留集结果一边调整。

优先只复读疑点小节；保留谱号、调号、同小节临时记号及跨行关系所需上下文。第二次读取不展示首轮音符答案，先冻结独立输出，再比较并按原图裁决。和上一轮错误信息共同进行的补救不称为独立复读。

同时抽查部分未触发区域，估计风险规则漏掉了多少错误。模型自报置信度只能作为候选信号，不能直接解释为真实正确概率。两次答案一致也不能自动清除原有疑点。

验收：在固定预算下，比较单次首读、局部重试、再加风险复读三种策略；报告正确恢复事件、新增错误、误报区域和总成本。只有收益可复现时才启用默认策略。

## 七、评测与发布验收

### 1. 评分范围

按清晰 PDF、扫描件、手机照片分别报告；再按密度、调号、临时记号、多声部及换谱号分组。抽页结果不外推整曲；增加整曲测试时，单独检查页行连续性、跨行延音和首尾覆盖。

用稳定的小节、谱表、声部语义及时间位置进行一对一匹配，声部编号先规范化，不能因编号名称不同直接算错。起拍容差、连音表示、延音是否按书写音头计数、倚音与重复音规则在评分前冻结。

| 指标 | 定义与用途 |
|---|---|
| 严格事件召回 | 正确匹配参考事件数 / 全部参考事件数；失败区域计入分母 |
| 严格事件精确率 | 正确匹配预测事件数 / 全部预测事件数；额外事件保留 |
| 漏音率与多音率 | 未匹配参考事件 / 参考总数；未匹配预测事件 / 参考总数 |
| 发声音高正确率 | 正确音高匹配 / 全部参考音，同时提供匹配覆盖 |
| 书写音名与显式记号正确率 | 仅在对应参考完备的范围评分；等音拼写单独核对 |
| 节奏与休止正确率 | 起拍、符值、连音、休止分别给出分子和分母 |
| 完全正确小节率 | 要求范围内无错音、漏音、多音和节奏等错误的小节 / 全部可评分小节 |
| 整行失败及拒识 | 格式失败、超时、主动拒识、部分输出分别计数 |
| 错误完成比例 | 被标为完成但独立参考发现错误的行 / 可评分的完成行 |
| 等待时间与用量 | 包含排队、补救、重试和复读；usage 缺失单列 |

同时报告首轮、自动补救后、独立复读裁决后和人工修改后的结果。不得用后处理结果替换首轮记录。播放速度或延长时长的练习默认值不参与纸面识别正确性评分。

### 2. 实验顺序

1. 固定基线与独立参考，先离线重放已有响应，确认错误拒收和字段校验改动的影响。
2. 固定模型、档位和首轮图像，评估结构化音高协议；单独记录输出长度及截断变化。
3. 在相同首轮结果上比较局部重试策略；重渲染和裁切变化是被测变量，记录各次哈希。
4. 增加高风险复读，与无复读方案比较增量收益。
5. 在未用于调试的作品与照片保留集上复验；模型随机性较大时执行预算内重复试验，报告逐曲差异和波动。

### 3. 发布条件

- 确定性规则回归全部通过，旧输入兼容策略与缓存版本可追溯。
- 固定基准中的严格召回和完全正确小节表现改善，精确率及各关键场景无不可接受退化；容许退化、预算和停止阈值须在实验前确定。
- 新增错误、失败区域和未知用量全部可见。
- 同一转录经保存、导出、回读后，音高、书写音名、时值、声部和延音等要求字段不被改变；这项只证明数据保真，不替代视觉准确率。
- 不预先承诺召回超过 90% 或其他通用百分比。目标值须结合固定样本的测量结果制定。

## 八、实施批次与交付物

| 批次 | 工作范围 | 交付与验收 |
|---|---|---|
| A 基线和可靠保存 | 冻结参考、未知速度、具体错误、严格复核类型 | 基线评分、离线响应重放结果、错误放行回归 |
| B 结构化读谱 | 统一音高与谱号、显式休止、声部与来源、协议适配 | 数据契约、音乐规则样例、固定图像对照评测 |

| D 风险复读与发布 | 独立局部复读、未触发区域抽查、保留集复验、导出回读 | 增量收益、误报与漏检、逐场景发布结论 |

版本记录分别保存整体提示词、升降号规则、数据协议、预处理策略和 Skill 版本。测试应检查各位置引用的版本是否正确，不要求不同组件的版本字符串相等。

模型选择与运行环境是实验条件：先确认使用满足项目要求的实际 Node 运行时，再区分环境失败与功能失败；若评估其他模型，应使用相同参考与范围独立计分，不能混用模型结果而不标注来源。

本轮报告聚焦识别准确度、覆盖和可信验收。踏板播放、反复播放展开、排版美化等扩展另行规划；当这些符号属于某次识别任务范围时，仍须显式记录未知或未支持，不能静默删除。
