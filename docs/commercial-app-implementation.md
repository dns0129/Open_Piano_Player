## 产品与运行边界

| 入口 | 构建与服务 | 内容 |

| 商业账号版 8793 | `npm run commercial:build`、`npm run commercial:start` | 账号、私有曲库、上传、识谱队列、额度和运营 |

本机版完整保留原有识谱入口、设置、任务恢复和找谱；模型连接沿用原有本机配置，历史任务与原谱继续使用。商业账号与额度控制走独立服务，商业后端不读取 Pi/Codex 凭据、本机模型设置或旧识谱 token，也不代理旧 API。本机服务不开放商业账号 `/api/v1`，两种识谱使用各自的数据和授权。

## 首次本机运行

需要 Node.js ≥22.19。在账号服务停止时执行运营开户：

```sh
npm run commercial:operator -- operator@example.test
npm run commercial:build
npm run commercial:start
```

也可在开户后双击 `启动琴伴.command` 并选择 **2 商业账号版**，它会先构建。访问 `http://127.0.0.1:8793/`，用上述邮箱验证码登录，再进入“运营”。本机预览不会发送真实邮件，验证码目录在账号页显示；验证码文件不通过 HTTP 提供。运营端可以建立普通邀请，受邀用户再自行申请验证码登录。邀请动作只建立资格，不发送邀请邮件。

已有普通账号也可以用 `commercial:operator` 提升；提升会撤销该账号现有会话，需要重新登录。HTTP 不提供自助申请运营权限。运营调整需要最近 10 分钟内邮箱验证；控制台提供再次验证入口。

默认不配置模型，接单关闭、成本上限为 0；此时账号、原谱私有保存、数字谱导入与练习仍可用。默认每人每月 5 个任务是可调整的初始值，不代表已发售套餐。

`QINBAN_ACCOUNT_DIR` 和 `QINBAN_ACCOUNT_PORT` 可以指定隔离目录与端口。本机数据库有进程锁，CLI 邀请、提升与维护命令须在服务停止时运行。不要删除锁文件来同时打开正在使用的 PGlite。关闭终端服务用 Control+C。

## 独立模型配置

凭据仅放服务端环境；不要填入网页、Git 或聊天。配置样例见仓库 `.env.example`。程序不自动读取 `.env`；使用进程环境或 Node 的 `--env-file` 加载，例如在构建完成后运行：

```sh
node --env-file=/绝对路径/商业版私有配置.env scripts/accounts.mjs start
```

| 变量 | 作用 |
| --- | --- |
| `QINBAN_HOSTED_API_KEY` | 独立识谱 API 密钥，无默认回退 |
| `QINBAN_HOSTED_API_BASE` | HTTPS Responses 兼容 API，默认 `https://api.openai.com/v1` |
| `QINBAN_HOSTED_MODEL` | 部署实际可调用的图像模型；缺省沿用项目偏好 `gpt-6.1-sol`，不保证该标识在某个 API 账号可用 |
| `QINBAN_HOSTED_INPUT_USD_PER_MILLION` | 部署使用的每百万输入 token 美元单价，必须显式填写正数 |
| `QINBAN_HOSTED_OUTPUT_USD_PER_MILLION` | 每百万输出 token 美元单价，必须显式填写正数 |

服务器只接受配置的 HTTPS 目标，不跟随跳转、不自动重试生成请求；浏览器不能指定地址、密钥、模型或单价。固定 high 推理、每行最多 60,000 输出 token，最多 250,000 计数输入 token。开启前须核实供应商支持图像、high、输出上限及 `/responses/input_tokens`。没有计数接口或返回格式不符时拒绝生成，不改用未估价请求。401/403/429 会暂停后续识别，等待运营处理。

生成响应还必须明确回显与部署值一致的 model 和 `reasoning.effort=high`；缺失、降档或返回其他模型时，不把请求参数冒充实际结果，也不按可能错误的模型单价结算。保留全部预留为未知费用、暂停后续调用，单独记录观察到的模型、档位与 usage，交由运营核对；不能保存该识别草稿。

这是新的服务端适配器，尚未用真实付费凭据验收。默认标识不是公开 API 可用性的证明，单价也不从项目订阅推算。每次调用保存当时的模型、推理档位、提示词版本和单价快照。

## 每人任务数规则

- 按 UTC 自然月计数，月初重置；默认上限和每人单独上限可在运营修改。名额单位是“任务”，不按页或谱行扣次。
- 一次提交 1–30 条用户确认的完整谱行，先占 1 个任务名额。同一个账号最多 1 个排队或运行任务，全站排队最多 100 个。
- 上传、保存原谱、预览、裁图、对照、播放、编辑和保存草稿不扣任务次数。
- 排队取消或所有生成请求均未开始，自动退回名额。已产生实际或不确定调用，保留该任务使用记录；运营可在任务停止后补偿名额。
- 主动“仅重试未完成行”建立新任务，成功行及裁图复用，只调用未完成行；若发生生成请求，占新任务 1 次。系统不自动重复计费请求，不自动做第二遍全谱复读。
- 幂等创建防止网络重发重复占用名额；服务端会话决定所属账号，不接受客户端 owner。任务名额与供应商费用是两本账，补偿名额不会把已发生费用归零。

## 全站成本上限

运营设置每日、每月和单任务成本上限，要求 `0 < 单任务 ≤ 每日 ≤ 每月`；全站同时处理 1–4 个任务。金额持久保存为整数美元百万分之一，避免浮点累计。界面用 USD 显示，日期边界为 UTC。

每行流程：计数输入 → 锁定全站设置与账本 → 检查上限并持久预留 → 发起生成 → 用量返回后结算。预留为：

```text
输入上界 = ceil(计数输入 × 1.2) + 1024
预留额（美元百万分之一） = ceil(输入上界 × 输入单价 + 60000 × 输出单价)
已知费用 = ceil(实际输入 token × 输入单价 + 实际输出 token × 输出单价)
```

单价单位是 USD / 百万 token。缓存输入按全价预留；reasoning token 已包含在输出中，不重复计价。预留立即计入全站日/月和当前任务成本，因此并发不能一起使用同一余额。预算不足则停止后续调用，保存成功结果；没有任何生成调用时退回该任务名额。达到日/月总额后，公开服务状态也显示不可识谱。

网络超时、响应丢失、进程中断或缺少可信 usage：保留完整预留为 `unknown`，暂停全站新调用，不能当成零成本。运营核对供应商账单后逐笔录入成本与原因，再保存运营设置恢复接单。实际计价超过预留也会暂停，需要检查单价与供应商计数规则。明确的参数、认证、限流等拒绝计零；408 超时、409 冲突及无法确认的错误保留完整预留，不自动重发。

上限约束的是本应用按配置单价计算的费用和预留，不是供应商最终账单或强制封顶保证。价格变化、计数偏差、供应商异常及本应用之外的调用仍需要供应商侧项目预算与账单核对。本轮测试用模拟单价与用量，不产生实际支出。

参考 [OpenAI 输入 token 计数](https://developers.openai.com/api/docs/guides/token-counting) 与 [reasoning / 输出上限说明](https://developers.openai.com/api/docs/guides/reasoning)。适配器按完整输出用量计费，未完成但已消耗推理的响应仍保留成本。

## 原谱、任务与检查边界

手机拍照、相册或文件选择支持 JPEG / PNG / WebP；一组最多 6 张、每张 20 MiB / 40 百万像素。PDF 最多 6 页 / 50 MiB，由服务器渲染。上传前可预览、移除并调整页序；HEIC 暂未支持，页面提示选择 JPEG。原始字节保留，EXIF 方向派生图沿用已有账号上传实现；不压小原照片来识音。

用户用上下边缘滑块逐行框选完整左右手谱表，按页序确认；任务明确标注 `user-selected-regions`，所有页都出现也不代表整曲无遗漏。每个选区在实际原图像素上裁切，保存原图坐标、裁图与所属关系。PDF 使用 2 倍渲染尺寸；不调用本地音符识别。

队列和每行结果写数据库。关闭网页不停止任务；重新打开查看状态。Worker 每 20 秒续租，租约 120 秒，失联任务转 `interrupted`，已派发但未结算的调用转 `unknown`，不自动重发。取消只停止后续工作，对已经发出的调用按实际或不确定用量记录。

所有行结构检查与跨行延音检查通过后，才可保存到私有曲库。保存的是 AI 待核对草稿，`humanConfirmed=false`；曲谱和原图参考进入现有编辑、播放、导出链。原谱印刷速度不明时，用用户选择的练习 BPM，并明确提示来源。没有音头坐标的结果只提供原图参考，不声称逐音原图定位。

结构检查、合成结果播放和数据持久性都不能证明识谱准确率。已有真实照片实验仍以 [原报告](phone-score-accuracy-20261021.md) 的范围与分母为准，本轮不新增真实付费识别准确率结论。

## 手机与基本运营

商业页使用手机单列、44px 以上主要操作、屏幕安全区、原图预览、实时任务进度、明确失败提示与保留重试输入。同一页面上传失败后保留文件和幂等标识；刷新会丢失尚未上传的文件选择，已保存原谱和已提交任务仍在服务器。返回任务无需保持浏览器常开。

独立 Manifest 与网络直通 Service Worker 提供主屏幕元数据和断网重连提示，不缓存 API、账号曲目、图片、Cookie 或私有页面。断网不能访问私有曲谱；没有宣称离线私有曲库。HTTPS 主屏幕安装、真实相机、iOS/Safari 后台切换尚需真机验收。

运营控制台提供：邀请、人工调整每月任务数、暂停/恢复账号、查看任务状态与失败码、日/月费用与预留、未知成本核对、名额补偿、公告与联系说明、用户反馈和回复、操作审计。暂停账号立即撤销会话，并要求停止其后续调用。暂停与名额变更跨身份库/控制库分两步执行，异常时可按相同绝对值重试；不声称跨库原子提交。

用户页显示最近 30 个任务、100 组原谱，首页曲目可继续分页载入。运营页首版显示最近 100 个用户/任务/反馈/审计索引，尚无运营列表分页与筛选；大规模运营前需补充。费用界面精确到美元百万分之一。

运营只能查看任务/费用元数据和用户主动提交的反馈文字，不能下载其他人的私有曲谱与原图。普通用户即使打开运营 URL 也看不到控制项，服务端角色检查返回 403。预算设置使用 revision 检查，避免运营之间覆盖；调整原因、前后配置、补偿与核对记录保留。

## 数据与正式部署

迁移为增量 `db/0002-accounts-commerce-v1.sql`，在 `0001-accounts-v1.sql` 后由独立维护身份执行。`qinban_control` 仅供受信任服务端角色处理全站状态；`qinban_private` 的任务、谱行、裁图引用、反馈强制 RLS。客户端不能直接连接数据库。

## 注册与邀请码

- **注册规则**：默认开放注册，任何邮箱通过验证码即可注册；运营控制台可关闭开放注册，此时新邮箱须填写有效邀请码或收到运营的邮箱邀请。登录与注册都是「邮箱 → 8 位验证码」两步，首次验证成功即创建账号。
- **邀请码**：格式 `QB-XXXXX-XXXXX`（10 位，去除 0/O、1/I/L 等易混字符）。数据库只保存邀请码的 HMAC 散列和末 4 位；完整码只在生成时显示一次。注册时填写的邀请码在验证码请求阶段先行校验（与邮箱是否已注册无关，不泄露账号是否存在），邮箱验证成功后在同一事务内加锁扣次并记录兑换；每个账号只能兑换一次。
- **赠送任务**：邀请码可附带一次性识谱任务（`qinban_control.task_credits`），在每月免费任务用完后才消耗；任务未实际调用而释放时退回。身份库与额度库在正式环境可分属两个数据库，赠送以兑换 ID 为主键幂等发放，失败时在读取额度或邀请列表时自动补发。
- **好友邀请**：每个账号可在「账号」页生成有限个单次好友邀请码（默认 3 个、有效 30 天、好友获赠 2 个任务），数量与赠送数在运营设置中调整；未使用的码可撤销以释放名额，不能兑换自己生成的码。
- **运营**：运营控制台「邀请码」区可生成（次数、赠送任务、有效天数、备注）、查看使用情况并停用；命令行：`npm run accounts:invite-code -- --uses 10 --bonus 3 --days 30 --note "首批用户"`（需先停止 8793 服务，因本机数据库同一时间只能由一个进程打开）。
- **迁移**：`db/0003-accounts-invites-v1.sql` 在 `0002-accounts-commerce-v1.sql` 之后执行，均为可重复执行的增量语句；本机启动时自动应用。

原谱组和任务裁图参与容量与引用保护；有任务或曲谱历史引用时不能删来源组，GC 不回收这些文件。终止任务的私有明细默认保留 60 天，已保存曲谱和历史引用继续保护原图；运营成本索引保留 UUID 与成本记录供核对，不存曲名、邮箱、图片或音符。账号完整备份包含已保存曲谱、历史与固定来源资料，不包含未保存任务明细、名额、权限和成本账本。

正式模式还需配置原账号环境变量：HTTPS origin、账号 secret、分别受限的身份/曲库 PostgreSQL 连接、SMTP 与发件人。数据库和私有文件必须使用持久卷并做一致备份。Node 监听回环，由同主机 HTTPS 反向代理转发正确 Host 与 `X-Forwarded-Proto: https`。运行角色不能是表所有者、超级用户或 RLS bypass。

首版按一个应用实例运行；队列与预算锁存数据库，生产多实例仍需要实际 PostgreSQL、共享文件与故障演练验证。本次首版验收不包含生产接入。后续已实现按月订阅与扫码支付适配，详见商业版订阅说明；真实收款联调、自动代扣续费、公开分享和外部对象存储尚未完成，不能从本机验收推断。

## 失败日志

商业版把需要运营排查的失败写到服务进程的标准错误输出，每行一个 JSON 对象（`time`、`level`、`event`、相关 ID 与精简后的 `error`）。日志不包含请求体、验证码、令牌、密码或支付凭据；`QINBAN_LOG=silent` 可关闭（测试默认关闭）。当前事件：

| 事件 | 级别 | 含义 |
| --- | --- | --- |
| `http.internal-error` | error | 接口返回 500；`requestId` 与返回给用户的一致 |
| `invite-credits.sync-failed` | warn | 邀请奖励未能同步到识谱额度，下次请求会重试 |
| `auth.code-delivery-failed` | error | 验证码邮件发送失败，该次验证码已作废 |
| `payment.checkout-failed` / `payment.query-failed` | warn | 支付渠道下单或查单失败 |
| `payment.notification-rejected` | warn | 支付回调验签失败：配置错误或伪造通知 |
| `maintenance.cleanup-failed` | error | 每小时的过期数据清理失败 |

账号与支付代码（`lib/accounts/` 中除识谱发布证据绑定的 `recognition-*` 外的文件和 `lib/http-kit.mjs`）带 `// @ts-check`，由 `tsconfig.accounts.json` 检查：开启空值等严格检查，但允许未注解的参数。`npm run typecheck` 同时运行两套配置。
