# 来源记谱契约与本轮改进

本次改进针对网易云批处理的真实失败类型，沿用 `gpt-6.1-sol / high`，没有重新开启定时任务，也没有新增供应商请求。

## 1. 统一来源数据

`lib/recognition-source-contract.mjs` 定义 `written-source-v2` 的显式来源扩展，供已有提交重放与复核数据接入；不从音符缺口推断拍号或休止。

- `meters` 与 `bars` 等长，逐项为 `[分子, 分母]`，首项须等于 `meter`。接入后成为 `coverage.measureTimeSignatures` 和全曲 `measureMap`，导出到 MusicXML/MIDI。没有显式证据时，超拍仍阻塞。
- 同拍同谱表的多个谱号必须各有唯一非负整数 `order`，较大者后生效。保留全部显示事件，不能由数组顺序裁决；缺少顺序、重复顺序或冲突调号仍拒绝。
- 延音跨小节保留原音的升降值，不能给新小节伪造显式记号。倚音沿用已有纸面符值/斜线/来源哈希契约，不把播放借时当书写时值。
- 声部非活动时间和源图明确休止分开。来源谱的 MusicXML 用 `forward` 推进非活动声部的时间；真实休止保留来源元数据。普通无来源谱继续支持传统排版补白。

本文件记录2026-10-30的离线来源层改进。当时生产模型提示词和工具schema未改；后续App实际模型接入见[2026-10-31接入说明](app-skill133-integration-20261031.md)，模型输入升级必须通过固定范围真实读取门禁，不能用离线重放冒充提示词准确率证据。

Skill 的 `written-evidence.mjs` 与 App 共同来源文件一致，`build-skill-core.mjs` 同步两者并重建核心，避免手工维护两套规则。

## 2. 先分类，再决定是否重读

`recognitionDisposition` 只分配后续工作，不自动修改音符、不重置调用预算：

| 类别 | 后续工作 |
| --- | --- |
| 数据契约/解析问题 | 保存提交，离线检查；不追加图片增强或供应商请求 |
| 变拍、事件边界或超拍映射疑点 | 先核对原图拍号、边界、节奏；不凭错误类型推断正确答案 |
| 图片质量/范围不完整 | 在原预算内准备更清楚的来源 |
| 音高、节奏等真实识读疑点 | 有界的定点原图复核 |
| 连接、认证、额度问题 | 保留进度，执行既有停止/恢复规则 |

原始错误及来源诊断保留于 checkpoint；不把外层 `SOURCE_RECOVERY_BUDGET` 当作根因。

## 3. 真实难例端到端验证

```sh
node scripts/verify-recognition-real-cases.mjs \
  --cases PRIVATE_MANIFEST.json --out NEW_DIRECTORY
```

清单格式为 `recognition-real-cases/v1`，每项提供 `id`、`job`、`pageManifest`；可用 `rowInputs:[{region,file}]` 重放已保存的真实提交，或用 `transcription` 选择保留额外记号/未处理项的版本。`originalPdf` 与 `libraryReadback:true` 开启独立验证库真实写入读回；`graceEvidence` 接入已有倚音纸面证据。所有路径相对清单目录解析。新输出目录必须不存在；失败输出保留，不自动覆盖。

本轮私有案例覆盖 Tennessee 的 3/4→4/4、银河赴约的谱号顺序、星空的16个倚音头、Towards 的跨行延音升降号继承、Kiss The Rain 的连奏弧待适配项、城南花已开的非活动声部。

验证包含提交解码、行内/全曲检查、当前转录与曲库事件一致、验证库读回、MusicXML往返（1e-6拍精度）、SVG全部导出音头保留、XML休止全部具有显式来源、无休止小节不出现渲染休止、MIDI与修改前项目版本比较，以及所有输入文件哈希不变。

`baselineSkill` 可指向归档的修改前项目 Skill。它无法表示新有序谱号时，案例必须显式设置 `baselineContractSupported:false` 并提供旧MIDI作严格对照；不丢弃新谱号来让旧校验器通过。旧全局安装Skill与项目版本不同造成的历史MIDI差异单列为 `previousArtifactMidiIdentical`，不混为本次排版修复。

私有原谱、提交、任务凭据和产物不提交仓库。公开测试使用合成的最小回归；真实原件通过本机私有清单重放。

## 4. 分开报告完成状态

来源链接/谱页、结果存在、结构通过、曲库导入读回、Skill草稿、符号保留、独立参考准确率、浏览器播放是不同指标。批处理报告增加 `stages`；没有独立参考的准确率和符号覆盖率写 `not-scored`，不能把72首导入当作72首准确无误。
