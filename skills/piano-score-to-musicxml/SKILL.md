# 钢琴谱识别与重绘

把原谱读取成可追溯的音符与记号数据，再用这些数据重新制谱。交付可编辑源数据、MusicXML、新排版谱面和校对报告；按任务需要交付 MIDI、简谱或导入琴伴。新排版可以改变换行、间距、谱表布局，不能未经要求改动原曲的音高与和声。

## 开始和输入

- 使用用户提供或已授权获取的全部谱页。只有曲名/分享链接时先取得真正的钢琴谱 PDF/图片，记录来源与总页数；封面、钢琴照片和网页截图不能充当谱页。需要登录时让用户操作登录。
- “声调”在本流程中指调号、大小调/调式和临时升降号。区分延音线、连奏弧、延长记号与踏板；区分波音、颤音和琶音。
- 使用当前可用的视觉模型或项目已认证的 AI 入口，遵守用户指定模型/思考强度。本项目既有偏好为 `gpt-6.1-sol` / `high`。Skill 自身不更换聊天模型、不提供模型服务，也不取得 ChatGPT 额度。没有视觉能力/凭据时说明缺口。
- 不使用本机 OMR 生成音符。允许本机做渲染、裁切、网格、音高算术、格式校验和排版。

## 1. 建立完整页与行清单

第一次使用工具时按 [数据与工具说明](references/data-contract.md#安装与命令) 安装依赖。以本 SKILL.md 所在目录作为 `SKILL_DIR`。

```bash
python "$SKILL_DIR/scripts/prepare_score.py" input.pdf --out work/pages
```

查看每张原图，记录双谱表系统行、谱号、调号、拍号、弱起和小节归属。封面/空白页要明确排除，不能静默漏页。原图保留不覆盖；裁切要保留原页/行映射与必要上下文。优先按系统行处理，多行之间保留谱号、调号及跨行连线的上下文。

## 2. 按音高、节奏和符号组织一次识别

识别前读 [读谱与校对](references/reading-and-checking.md)，使用其中的升降号规则 `accidentals-v2-20261018`。

- 先从谱号和音头线间位置读出**字母、八度、实际升降值**，再算 MIDI；同时保存原谱显式记号。保留降 B 与升 A 的不同写法。原谱谱表、演奏手别和重排谱表分别保存；显式休止和独立声部范围不能用时间轴空白代替。
- 按谱表、字母、八度和小节维护临时记号状态；核查还原、跨声部、跨小节延音、换谱号和八度记号。同拍相关音成组处理，显式记号矛盾时保留疑点，不能按数组顺序决定。
- 同一次行级读取中，在确定音高后填充时值、休止、多声部、三连音/连音、附点、延音目标和 BPM 音符单位，再检查力度、重音、断奏/保持音、波音/颤音、琶音、倚音、连奏弧与延长记号。这是字段推导顺序，不要求每个阶段单独调用模型。
- 不先把五线谱扁平化为简谱来推导节奏。完整的音高/书写音名/时间轴数据才是共同源，简谱与五线谱都从该源生成。

原谱速度未印、不可辨或未知时分别记录状态，不能用练习默认速度冒充原谱数字；允许先保存音符与草稿。

按 [数据契约](references/data-contract.md) 写入 `transcription.json`。若要通过项目现有 Pi/API 工作流识别或导入曲库，再读 [琴伴接入](references/app-integration.md)。旧的四元组响应不包含全部演奏记号，不能把该结果直接当作全功能识谱完成。

## 3. 原图复核和增量重读

先确认每页每行及左右谱表全部提交；再检查小节时间轴、调号/临时记号、同音延音和复音完整性。优先重读疑点所在原图区域，保留成功行，不重跑已成功的全部谱页。

默认不自动追加全谱第二次 AI 识别，沿用琴伴主线已取消全谱二次调用的策略。原图检查和确定性校验贯穿首轮；有疑点时只定点重读。用户要求独立复核/对比实验时，再让第二次读谱只看同一原图、谱号/调号等上下文和相同字段规范，先独立产出，再比对首轮；不要先给首轮答案让它附和。两次一致只是复核证据，不能当作独立真实准确率。无法确认的音/符号放入 `issues`，不要按曲名记忆或和声习惯补写。

## 4. 校验并重新制谱

```bash
node "$SKILL_DIR/scripts/score_pipeline.mjs" \
  --input work/transcription.json --manifest work/pages/manifest.json \
  --out work/result
```

工具核对实际页图哈希、全部页/行/小节归属、原谱记号状态、音高和时值一致性，生成：

- `transcription.json`：可编辑的逐音转录和原谱证据，保留书写音名。
- `score.musicxml`：原生音符、双谱表、节奏和记号；可在支持 MusicXML 的编辑器继续编辑。
- `engraved-*.svg`、`index.html`：根据音符重新排版的五线谱，不嵌入原图。
- `score.mid`、`score.qinban.json`：播放/练习数据。
- `report.json`：页数、覆盖、小节/音符数量、未解决项、播放差异及实际 usage 的字段统计。
- `artifact-manifest.json`：本次完整产物集的输入/实现指纹和文件哈希；文件齐全不等于原谱已人工确认。

复核标记必须为真正的布尔值。按原图完成每个小节的核对后，记录与当前内容哈希绑定的逐小节复核证据；修改音符、来源或相关延音后，失效的小节需重新核对，具体字段见数据契约。工具只能检查复核记录是否一致，不能证明复核动作真实发生。

有未完成校对或暂不支持的符号时，默认拒绝“完成”导出；仅预览可加 `--draft`，交付时明确草稿。生成失败时保留暂存，确认旧进程结束后可用同一输入/选项加 `--resume` 继续；不覆盖旧成果或已被用户修改的文件，详见数据契约。工具能校验结构与算术，不能证明看图读音正确。工具不支持的原谱符号保存在 `notation.unhandled`；适配标准 MusicXML 或交由合适编辑器完成后才能清除该阻塞项。

## 5. 检查、交付和可选导入

打开新排版谱面，按原页清单逐小节抽查布局，重点检查升降号密集处、和弦、连音、跨行延音和左右手。需要全谱校对的任务必须覆盖全部小节；抽查不能写成全谱准确率。

更换和弦、移调、大小调改写属于用户授权后的编辑，保存原版与修改版；小调改写不是只改 `<mode>` 字符串。简谱从已确认书写音名和调式推导，保留八度、临时变音、时值和声部分离。

完成报告用简体中文，区分“模型复核”“人工确认”“结构/播放通过”“独立参考评分”。仅在有独立参考、对齐和计数时报告准确率。计时覆盖首轮、排队、重试和校对；Token 仅使用实际 provider usage，缺失写未知，不能用订阅额度/上下文估算代替。详见 [评分与耗时口径](references/reading-and-checking.md#评分与耗时口径)。

用户要求导入/发布时，验证目标曲库真实写入和读回，并区分本地、GitHub 曲库和云端 App；未授权则只交付制谱文件。
